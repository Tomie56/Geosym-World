## 一、核心判断

原有“数据为中心的大模型算法与工程”定位仍然成立。更新应重点突出两项进展：

1. WebCode 已形成覆盖召回、八维质量建模、来源策略、版本化交付及验收的完整生产流程，并有最新规模与测试指标。

主要问题不是所有旧数字都错，而是历史版本与最新版本混用，以及部分结论强于目前提供的证据。

### 方法与指标口径

- 八维独立请求是标注设计，不能据此声称八维在统计上互相独立。推荐“八维分别标注，降低跨维度评分干扰”。
- 需要确认 Pairwise Win Rate 与 Diff>=1 Win Rate 的配对集合、平局处理和分差定义。当前数值本身不构成矛盾，但不宜在缺少定义时强调二者差异。
- 需要确认 ID 去重、稀缺分数增广及 train/val/test 划分的执行顺序，确保同源重复样本未跨集合。这里只标记证据缺口，不推定存在泄漏。
- 优化总结中的严格/宽松规则属于迭代过程；最终交付记录指向宽松版 V3 主过滤器及来源特定阈值、V2 高分救回分支，应以后者描述实际交付。
- RubricFlow 的两轮八维、1-10 分，与生产质量体系 P0-P3、示例 5>4>3>2>1 不应直接合并。需明确分数量表和两者关系。
- “抗 Hacking”目前是方法目标；独立标注、跨模型复核和排序测试尚不足以证明抗攻击能力提升。可改为“针对评分规则漏洞与边界误判迭代监督”。
