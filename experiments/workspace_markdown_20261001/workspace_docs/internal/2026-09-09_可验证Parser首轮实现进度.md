# 可验证 Parser 首轮实现进度

日期：2026-09-09。目标依据：`docs/reports/2026-09-09_可验证几何解析重建与再合成开发计划.md`。实现仓库：`/data/Geosym127K/Geosym-World`。本轮未修改 GeoClaw，未运行大规模合成、模型调用、训练或真实 benchmark。

## 已实现

### P0：契约和事实边界

- 新增 versioned `ParseGraph`：evidence、object、relation、quantity、region、target、conflict 均为严格类型，采用稳定 ID、引用完整性、依赖环检查、canonical serialization 和 checksum。
- 数学值使用受限 `MathExpression` AST，不执行来源字符串；对象 geometry 按类型限制字段，并在 schema 边界拒绝非有限坐标、负半径、错误方向、非法 exact AST 和不兼容字段。
- 新增 `source_assertion`、`entailed_fact`、`realization_fact`、`generation_parameter` 四类事实 scope。来源推导不能依赖 coordinate witness 或生成参数。
- Parser 结果继续以 `PROPOSED` hypothesis 保存，禁止直接携带持久 State。

### P1：来源隔离和结构评测

- 新增 `ParserSourceManifest`、三种 protocol、公开输入物化、asset hash 和 checksum-bound 私有 reference。
- 新增 `prepare_parser_inputs_v0`：严格读取私有 source catalog，检查重复 source，按内容 hash 物化 opaque 图片，分离公开 `parser-input.jsonl` 与私有 `source-audit.jsonl`，并输出可追溯 manifest。
- 合成导出新增 `*.typed-parser-reference.jsonl`：由 verified `FormalGeometryState` 和实际 `RenderScene` 共同投影 typed GT，包含真实像素变换、精确表达式 AST、区域、公开条件、目标和点名绑定；运行时 Parser 不读取该 sidecar。
- 合成 Parser 输入改为 opaque sample ID 与 content-addressed PNG；即使数据集只导出 SVG，Parser 侧也获得匿名 raster，模板 family、参数化 record ID 和命名图片路径仅保留在私有 source audit。
- `ParseGraphEvaluator` 先做对象匹配，再独立评分 relations、quantities、regions 和 targets；对象匹配不读取 GT relation。
- evaluator 将“点对象直接名称”和“文字对象经 `binds` 关系得到的点名”视为同一种名称投影，同时仍独立检查文字对象与绑定关系，避免表示方式差异破坏对象匹配。
- evaluator 不读取 GT binding 来选择对象匹配；新增 label、binding、topology 独立指标，并按规范数学值比较等价表达式和角度单位。
- 指标能识别位置错误、绑定错误、未匹配对象及缺失孔洞；区域并集/交集忽略操作数顺序，边界允许循环起点差异。
- 新增 `evaluate_parse_graph_v0` CLI，严格检查 prediction/reference ID 集合并生成逐条结果和 manifest。
- evaluator 新增逐组件 exact-match、组件 Sample Accuracy、五核心组件 perfect rate 和八组件 Perfect Parsing Rate；原五组件 `macro_score` 保持不变，避免平均 F1 掩盖整图错误。
- 新增可信人工 GT 数据链：primary annotation、independent review、disagreement 和 adjudication 均为严格 schema，并绑定同一个 ParserInput checksum、source manifest checksum、source ID 和 guideline version。
- 人工链明确拒绝 `model_assistance=true`、模型分数候选、同一人标注与复核、未解决分歧、未完成裁决及被篡改记录；可选策略要求第三位独立裁决者。
- 新增 `materialize_parser_references_v0` CLI：批量校验公开输入、私有 source audit 和三阶段人工记录，分别输出 evaluator reference、含人员与上游 checksum 的私有 lineage，以及全文件 hash manifest。
- 冻结 `parser-gt-v1` 标注手册，明确对象纳入、匿名交点、标签/数值绑定、关系角色、区域孔洞、target、exact/witness 边界和双人复核裁决清单；annotation schema 只接受该版本，未知版本立即拒绝。

### P2：无模型依赖的 typed baseline

- 新增 `TypedDiagramParserV0`，输入仅为 `ParserInput`。
- OpenCV 路线生成线段、圆、端点、交点、文字区域和基础拓扑候选；辅助线交点以匿名稳定对象进入图，不因没有点名而丢弃。
- 线圆与圆圆求交进入同一 typed topology：分别保留零、一、二交点，切触和穿越作为 relation metadata，线上的曲线交点进入 `ordered_points`。
- 线候选增加图幅相对最短长度、无向角规范化和共线分组传递闭包，减少圆弧局部切片、文字笔画及反向 Hough 重复段；版本和阈值进入 ParseGraph metadata。
- OCR 保持可注入接口，默认不猜文字；视觉平行/垂直只作为带证据提案，并标记为不能自动当 exact relation 接纳。
- 新增首个确定性 marker grounding：只有在两条已检测支撑线的有限交点附近存在连续 L 形短笔画时，才生成显式 `right_angle` marker 对象；对象绑定两条 segment，`perpendicular` 关系依赖 marker，detector 阈值和版本进入 metadata。
- 同一支撑对已有显式直角 marker 时，抑制较弱的纯角度 residual 候选并记录 ID；没有 glyph 的近似 90 度交点仍只是不能自动接纳的视觉度量提案。marker 候选同时透传给 clean baseline 和 hybrid evidence graph。
- marker baseline 扩展为四类显式 glyph：`right_angle`、`parallel`、`equal_length_tick` 和 `angle_arc`。线性 marker 先估计每条支撑线的实际栅格笔画宽度，再在支撑带外匹配刻线/箭头并排除已知端点和交点；角弧要求曲线核心离开两条支撑带，并在至少三个相邻半径上稳定出现，避免把普通粗线顶点误识别为弧。
- 每个可见 glyph 独立成为带 bbox、path、score 和 support 引用的 marker 对象。平行箭头要求两个独立 support；等长刻线先绑定到全段或由已有端点/交点限定的唯一相邻子段，两个不同的已绑定区间才提升为依赖两个 marker 的 `equal_length`。同一合并直线上的两侧刻线可在已知交点分段时表达子段等长，但 Parser 绝不根据刻线位置自行创造中点；两个刻线仍落在同一未分段 support 时只保留 marker。
- 角弧使用 detector 的 ray sign、唯一支撑交点和每条射线方向最近的已知拓扑点恢复有序 `(arm, vertex, arm)`；恰好两个已完整 grounding 的同组角弧可生成依赖两个 marker 的 `equal_angle`，缺失方向、顶点或角臂点时只保留证据。两个等角共享恰好一条已 grounding 射线且方向符合内/外角平分时，再编译依赖该 `equal_angle` 的 `angle_bisector`，最终仍由 Geometry State verifier 复核。
- 点名 grounding 仅接受受限点名格式；唯一近邻生成带 evidence 的 `binds`，距离相近的多个候选进入 unresolved conflict，不直接改写点对象。
- 点名绑定增加一对一约束；同名绑定或多个点名竞争同一点时形成 conflict，admission 还会二次阻断非唯一绑定及其下游候选。
- 新增图面数值 grounding：OCR 已识别的数字、根式、分式、幂和 `pi` 可按有限线段内部投影生成 length quantity 候选；多条近邻线段保留为 unresolved conflict，非法表达式和无支持对象进入分阶段 issue。
- 图面数值的空间近邻只提供 localized binding evidence，默认严格 admission 会 abstain，不会把“离某条线最近”静默提升为可信长度；`A`、`A1` 等合法点名不会误分类为数值。
- 新增公开题干显式关系解析，首批支持 parallel、perpendicular、equal_length、midpoint 和三点 collinear；关系对象必须通过唯一点名 binding 解析，候选显式依赖对应 binding。
- 题干关系引用不完整或有歧义时只保存 localized text evidence 和 `reference_unresolved` issue，不创建半绑定关系；`AB = CD` 不再被误解析为数值符号表达式。
- 题干关系与同一对象上的视觉角度候选一致时抑制较弱的视觉重复项并记录其 ID；若图文不一致则不掩盖差异。
- 新增安全题干表达式 parser，支持数字、符号、四则、幂、根号和常见 LaTeX 分式，不对来源文本调用 `eval` 或 `sympify`。
- 显式 `AB = expression` 长度条件在点名和线段唯一时生成 quantity，并显式依赖相应 binding；非法表达式或对象歧义只保留 unresolved evidence。
- 问题文本先做保守 target 类型提议；显式线段长度目标仅在两个点名绑定和唯一线段拓扑都成立时解析对象，并显式依赖相应 binding，否则保持 unresolved。
- 新增 provider-neutral `ExternalParseGraphPrediction` 和 `RecordedParseGraphParser`：固定的直接 VLM/专用模型输出可在不调用网络的情况下进入同一 typed proposal、pixel verifier、admission、reconstruction 和 redraw 链。
- 新增 checksum-bound `OCRImagePrediction` 和 `RecordedLabelRecognizer`：离线 OCR JSONL 同时绑定图片 SHA-256、完整 detector 文字区域 ID/bbox checksum、backend/model/revision 和逐框置信度；图片变化、区域漂移、漏/多图片、重复框和 payload 篡改均硬失败。verified CLI 支持互斥的 `--ocr-predictions`，manifest 保存 sidecar hash 和模型配置；OCR 结果仍只作为带 provenance 的 observation 进入后续 grounding/admission。
- 外部输出严格记录 backend、model、revision、prompt、decoding、usage 和 request ID，绑定公开输入 checksum；拒绝伪装 native/human/verified provenance、私有 source ID、formal state、答案、solution、scene、derivation、source manifest 和敏感密钥字段。
- `parse_reconstruct_v0 --external-predictions` 在写结果前核对完整 ID 集合，并把外部预测文件 hash 与模型配置写入 manifest，从而支持 OpenCV 与直接模型路线的同协议比较。
- 新增 clean raster 填充外观候选：OpenCV 提取浅色彩色连通组件、外轮廓、粗粒度内部空隙、颜色、bbox 和分数，并在 typed 层按轮廓包含、内部覆盖、面积相容及唯一 margin 绑定到直线 planar face。
- 填充组件无法唯一绑定、或关闭 planar-face 推断时，仍作为 localized evidence 保留；唯一绑定后只记录 `fill_status=observed`，不把普通 polygon fill、target 高亮或内部文字空隙直接提升为 `shaded`/`hole` 语义。
- clean baseline、hybrid evidence board/graph、script observations、直接模型上下文和 visual overlay 均透传同一 `fill_regions` 候选，避免不同 Parser 路线丢失该证据。

### P3：Admission 和受限重建

- 新增 candidate-level `ParseGraphAdmission`，按 confidence、evidence precision、依赖和 conflict 做 admit/reject/abstain，不修改持久 State。
- 新增独立 `PixelTopologyVerifier`：对有限直线支撑和圆使用方向感知笔画采样，复核路径连续性、交点局部双支撑和点序；报告绑定 ParseGraph checksum、源图 hash、阈值、版本和逐候选指标。
- verified workflow 默认要求 image-origin 结构候选具有像素拓扑检查；失败直接 reject，未知或缺失检查 abstain，后续重建成功不能反向替解析候选背书。
- `ParseGraphReconstructor` 只接受 admission report；对象按依赖 DAG 编译，与输入顺序无关。
- 支持 point、segment、line、ray、circle、arc、polygon、部分 region/composite region、受支持 relation、quantity 和 target。
- exact 反构造新增受限交点规划：线线唯一交点直接生成；线圆/圆圆切点直接生成；两交点必须带显式 branch selection。缺失或竞争分支输出 `branch_ambiguous`，不读取像素偷偷选择 exact 解。
- 新增有限 exact branch enumeration：同一支撑对的双交点只枚举两种 ID-解双射；多个独立分支组做确定性笛卡尔积，每个分支独立重放验证，并由 `max_branches` 硬限制组合规模。
- exact DAG 新增 midpoint、垂足、内分比例点和正向射线距离点；新增过一点作平行线、垂线及内/外角平分线。输入对象顺序不影响构造，竞争定义报告 `construction_ambiguous`，相互定义的直线循环报告 `reference_unresolved`。
- exact DAG 还支持从安全 numeric angle AST 构造相对已知线的过点直线，并对声明式 `angle_from_line` 做精确方向复验。
- 圆可从已接纳 radius/diameter quantity 得到 exact 半径；等价约束合并，冲突约束报告 `condition_conflict`，不回退到像素半径。
- 构造器自动生成的交点、midpoint、垂足、比例点、射线距离、平行/垂直线和角平分关系可保留原 ParseRelation ID、依赖、evidence、confidence、score kind 和候选 metadata。
- 当 GT 已给 exact 坐标时，垂足、比例点、射线距离和角平分关系走声明式 State payload，并由 TraceVerifier 独立复验；关系为假会阻止 State 落盘，而不是仅因对象可构造就返回 exact。
- exact 模式只接受 expression AST；pixel-witness 模式显式标记为 realization。输出 exact/numeric_witness/partial/unsupported、free symbols、未放置点、分支歧义和 unsupported candidates。
- 构造 trace 先验证再落 State；source facts 与 coordinate closure 分开导出，并保留 parser provenance。

### P4/P5：重绘、再合成和批处理

- `source_redraw` 从 admitted observed graph 重画，只显示明确来源标注。
- `semantic_redraw` 需要已验证 State，并禁止自动补 inferred relation markers。
- `resynthesis` 仅允许 exact reconstruction，支持显式选择 seeded exact 2D 刚体变换或受限 similarity。similarity 统一缩放根点、圆半径和射线距离，并重放 trace、复验关系和 topology signature。
- similarity 在存在绝对长度、半径、直径、坐标、周长、面积、弧长、体积或有量纲 constraint target 时立即拒绝，不自动回退 rigid；当前只覆盖无量纲 source assertions，不等同于一般约束保持参数编辑。
- 三种输出共用现有 `RenderScene`、SVG 和 PNG 后端，保留 lineage、invariants、verification 和 checksum。
- 新增 `parse_reconstruct_v0` CLI，支持进度、分模式产物目录、输入/输出 hash、状态/诊断/文件统计和 manifest。
- 新增 `docs/PARSER_PIPELINE.md`，记录协议、命令、支持范围和明确限制。

## 未完成

- 人工 GT 契约和物化工具已经实现，但尚无许可明确、真正完成双人标注与裁决的真实题图，因此不能报告真实 Parser 精度。
- 已具备 provider-neutral 固定 ParseGraph 输出重放接口、checksum-bound 外部 OCR replay、四类确定性 marker baseline、同线已知拓扑子段等长、ordered-angle/equal-angle、共享射线角平分和 clean 彩色填充外观 grounding，但未集成或调用具体 OCR/VLM/专用神经模型，也未进行模型路线比较；独立/歧义角平分 glyph、语义阴影判定及曲线区域绑定仍未完成。
- 未实现从一般无序约束恢复 exact 坐标的非线性求解、自由参数规范化和多分支搜索。
- 未实现一般 native CAD/vector importer。
- 未实现曲线边界区域的逆向 Boolean 重建。
- 非刚性再合成只新增了无绝对量纲条件下的 exact 2D similarity；一般非均匀参数修改、条件同步重写和新答案 supervision 仍未完成。
- 未运行需单独批准的 500 条合成回归和真实 benchmark。

## 下一步建议

1. 冻结 `parser-gt-v1` 标注手册，建立 20-50 张许可可追溯的 clean 2D 小集合，通过现有 annotation/review/adjudication 链独立复核 binding、孔洞和 target。
2. 用当前 evaluator 得到 OpenCV baseline 的真实分组件错误分布，重点测量 marker 在压缩、缩放、线宽和文字邻近扰动下的 precision/recall，再决定 OCR、VLM 或专用模型的投入点。
3. 并行增加基于 GT ParseGraph 的约束规划器，只实现可证明的三角形/平行线/圆子集，显式报告欠约束与多解。
4. 在 exact 子集上增加非刚性参数变体和不变量验证，再执行四类端到端案例验收。
