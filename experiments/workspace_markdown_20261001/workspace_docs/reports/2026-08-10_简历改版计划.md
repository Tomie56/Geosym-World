## 3. 实习经历修改

### 3.1 九坤投资 / IQuest Lab

九坤是当前简历中最重要的工业训练经历，保留四个层次。

#### 3.1.1 基座模型预训练数据交付

重点写清：

- 主导 WebCode 数据从 2.5T 原始语料到 60M 高质量样本、380B Tokens 的全链路交付；
- 完成 13 张版本化 Lance 数据表入湖；
- 使用 A0.5B/A1B MoE 模型验证数据训练价值，并在 MBPP、HumanEval 上较上一版数据取得提升。

表述重点是“围绕目标模型能力完成数据设计、交付和训练验证”，而不是文件处理或表数量本身。

#### 3.1.2 Recall 与 Quality Scorer

明确区分两个任务：

- Recall 判断文本是否包含值得保留的 CS 知识或代码技术载体，核心是避免在上游错误丢弃真实相关内容；
- Quality Scorer 在召回后评价技术深度、可靠性、工程价值、信息密度和文本完整性，用于排序、加权和进一步筛选。

保留的核心结果：

- 新旧数据合并形成 532 万条、正负比 1:2 的 Recall 训练集；
- Recall 模型 Validation F1 为 0.9536；
- 已落地的单头质量 Scorer 在 GPT-5.5 标注的 30K 验证集上 Pairwise Win Rate 为 0.954；
- 生产推理扩展至 256 卡 H200 集群，单日吞吐约 50 亿条。

Validation F1 与 Pairwise Win Rate 属于不同模型、不同任务，正式简历中必须分别标明，不能混用。

#### 3.1.3 OnlineRubrics / RTD

OnlineRubrics/RTD 的核心不是普通 Prompt 改写，而是让数据判定标准能够基于证据受控演化：

- 从同语言、同来源和相近主题的差异样本中发现缺失规则与边界；
- 使用异构模型交叉 Critique，并在隔离 Validation 上验证；
- 候选规则只有经过人工 accept/revise 后才能进入下一版 Rubric；
- Recall 与 Quality 的规则、数据和指标保持严格隔离。

可写入简历的阶段成果：

- 在 48K 样本上完成 Recall Rubric 首轮迭代与版本比较；
- 对 128 条争议样本进行独立语义盲审，新版 P1 判断以 76:45 优于旧版 V0，另有 7 条等距；
- 结果证明 RTD 能发现有效边界并改善定向争议样本，但尚不能表述为在完整人工金标上稳定全面优于旧版。

八维 Quality Rubric 与多头 Scorer 仍处于标注、解析和训练闭环建设阶段。正式简历只能写“设计并推进”，不能写成已经完成训练或取得确定提升。

#### 3.1.4 数据训练效用建模

这一部分用于直接体现对模型训练的理解：

- LLM Score、PPL 等先验质量信号不等同于真实训练价值；
- 进一步结合 Loss Trajectory、梯度对齐和 Data Influence 等后验信号，估计数据对目标能力的边际贡献；
- 研究最优质量阈值与数据多样性的 Trade-Off，并通过训练实验而非静态评分决定筛选策略。

九坤经历最终形成以下递进关系：

```text
规模化数据交付
  -> Recall 与 Quality 建模
  -> OnlineRubrics 标准迭代
  -> 下游训练效用验证
```

## 4. 研究方向与代表工作

研究部分不再按单位和日期平铺，而是组织成三条连续主线。主次顺序已经确定。

### 4.1 旗舰方向：Rollout Steering、表征干预与 RLVR

Rollout-Time Representation Steering / Online GRPO Rollout Steering 是整份简历的旗舰研究，不是 PML。

核心研究叙事：

> 标准 RLVR 依赖 verifier reward 更新参数，但不显式保存同一 prompt 下成功与失败轨迹的内部状态差异。本项目将 mixed-outcome rollout group 压缩为跨 iteration 的 activation-space proposal state，用它改变后续候选生成，并始终训练和评测未注入策略。

简历重点突出：

- 基于 verl 和 vLLM 完成从正确/错误 Rollout 配对、Activation 提取、方向估计、在线注入到未注入 checkpoint 验证的完整闭环；
- 支持 Linear、Logistic、RFM、Cluster Vector Bank 及随机方向等方法和严格控制实验；
- 理解 Steering 在该工作中的作用不是简单改变一次推理输出，而是调整 GRPO 的 Rollout Proposal 和探索分布，使策略从新发现的高奖励轨迹中学习；
- Validation 时关闭 Steering，只评估未注入策略，避免把推理时增益误写成参数训练收益。

结果口径必须保守：

- GRPO 将 Math500 Mean@8 从 47.33% 提升至 61.42%，可作为已建立的训练基线；
- Cluster K=4 当前单次在线实验出现明显正向信号，但随机方向也带来部分提升；
- 在 multi-seed、shuffled/sign-flipped/fixed/stale vector 对照完成前，不写“稳定优于 GRPO”或“发现通用正确性向量”；
- 若严格对齐实验形成稳定结果，再将对应提升数字写入最终简历；否则突出研究框架、训练闭环和严谨的机制验证设计。

### 4.2 补充探索：PML 与选择性表征干预

PML 作为表征干预方向的探索性工作，不作为旗舰项目。

保留的核心思想：

- Localization 本身不能说明一个方向在不同干预强度下是否存在收益高、副作用低的选择性区间；
- PML 预测目标收益、语义邻域损伤和通用能力损伤，并据此选择干预系数或 abstain；
- 项目用于补充对 Steering 选择性、风险和可预测性的理解。

摘要中缺失的 strength 和 AUROC 数字不得推测或补写。项目在研究部分保持简洁，主要成果通过 AAAI 2027 投稿条目体现。

### 4.4 数据价值与高效训练

以 One-Step-Train 为代表工作，形成“研究方法 -> 工业实践”的对应：

- 将数据选择重构为增量优化效用排序，用轻量代理模型单步更新后的 Delta Loss 估计 Train-Value；
- Top-20% 数据子集超过 LLM-as-a-Judge 基线 5.6 个百分点、超过 Full-SFT 8.8 个百分点；
- 降低 GPU 训练时长成本 43%、总计算开销 17%；
- 通过代理模型训练阶段消融发现，约 5% warm-up checkpoint 能更好平衡成本与抗噪性。

九坤的 OnlineRubrics、Recall/Scorer 与训练效用建模作为这一研究方向的工业规模延伸，但研究部分不重复实习中的同一数字。

## 6. 重点体现的模型训练理解

最终文案需要持续体现以下判断，而不是只罗列工具和数据量：

1. **数据任务需要分层。** Recall、Quality 与 Training Utility 的目标和错误代价不同，不能用同一套标签或 Rubric 混合处理；
2. **静态质量不等于训练价值。** 教师模型评分和 PPL 只能提供先验，最终要由梯度、Loss 轨迹和下游能力变化验证；
3. **训练数据策略必须通过模型实验闭环。** 数据阈值、增强、混合比例和筛选方案应通过 SFT、RL 或预训练对照确定；
4. **Rollout 分布是 RLVR 的关键训练对象。** Steering 可以用于改变候选发现和探索，而最终收益必须在未注入策略上验证；
5. **研究结论需要匹配证据强度。** 单 seed、峰值或弱监督共识只能作为初步信号，不能写成稳定泛化结论；
6. **可验证监督能连接数据与训练。** GeoSym 的符号求解、Answer Verification 和 Benchmark 为 SFT/RLVR 提供可审计的训练与评测信号。
