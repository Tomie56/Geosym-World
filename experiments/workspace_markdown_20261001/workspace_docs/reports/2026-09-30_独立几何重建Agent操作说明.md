# 独立几何重建 Agent 操作说明

## 任务目标

本实验用于判断视觉模型或 Agent 自身是否具备“看图重建几何模型”的能力。

输入是一张几何题图和可能存在的题目文本。输出必须包含：

1. 一份可审阅的几何数学模型 JSON；
2. 一张根据该 JSON 重新绘制的图片；
3. 一个包含原图与重绘图的 `contact.png`。

这不是现有 Parser 的回归测试，也不是验证 Parser 当前实现。请把它当作一个全新的几何重建 Agent 实验。

## 重要边界

执行过程中必须遵守以下规则：

- 不读取现有 Parser 的 hypothesis、admission、state、scene metadata、解析结果或旧的 redraw 作为输入。
- 不根据已有 Parser 的失败原因预设答案。
- 不把“能够生成合法 JSON”当成重建成功。
- 不因为某个测试样本失败就增加只服务该样本的特殊规则。
- 不将图片直接当作背景贴回输出；必须从模型 JSON 重新绘制几何对象。
- 不要求所有图片都能恢复精确数学坐标。题图可能只提供拓扑和约束，不能凭空补充不存在的信息。
- 每张图片独立处理，不能把前一张图的点名、形状、关系或假设带到下一张图。

允许使用：

- 原始图片；
- 题目文本或题干中的有限文字；
- 通用图像读取和绘图工具；
- 通用几何库；
- Geosym-World 的基础几何对象和渲染器，但不能调用现有 Parser 流程。

## 输入数据

本轮 20 张图片位于：

```text
/data/Geosym127K/Geosym-World/artifacts/parser/evaluations/real_multisource_tangent_v1_20260928/run_skeleton_replay_v1_20260930/json
```

每个 JSON 中的 `parser_input.image` 是原图路径，`parser_input.question` 是可选题干。读取时只使用这两个字段，不读取其中的 formal state、scene metadata 或任何历史解析结果。

建议先建立一个输入清单，记录：

```text

```

不要修改原始输入目录。

## Agent 的实际工作方式

对每张图独立执行以下步骤。

### 1. 先看图，再建立几何对象表

先识别人类会认为属于图形本身的内容：

- 顶点、端点、交点、圆心、辅助点；
- 线段、直线、射线、延长线；
- 圆、弧、扇形、半圆；
- 三角形、四边形、多边形、阴影区域和带孔区域；
- 由虚线、垂线、平行箭头、等长刻痕、角标、阴影边界表达的语义。

点名存在时必须保留原点名。没有字母时使用 `P1`、`P2` 等稳定名称，并在 `uncertain` 中说明这些名称是 Agent 分配的。

交点必须显式成为 point。不能把“某条线与另一条线的交点”只留在关系字符串里。

### 2. 区分可观察内容和推断内容

模型中必须区分：

- `observed`：图中直接可见的对象、线、标记和数字；
- `inferred`：根据标记或题干推断的平行、垂直、相切、中点等关系；
- `assumed`：为了生成可画的种子而采用的自由坐标或未确定方向。

如果数值不完整，不要强行构造精确坐标。应保留约束，并使用合理的视觉 scaffold 画出合法种子。

### 3. 恢复结构关系

至少检查以下关系：

- 点在线、点在线段、点在圆上；
- 共线、相交、重合或延长；
- 平行、垂直、角平分、中点；
- 等长、等角、相似、全等；
- 圆心、半径、直径、弦、切线、相切；
- 区域边界、差集、孔洞、阴影和复合区域。

不要把“图形看起来像长方形”自动写成 `rectangle` 或四个直角，除非图片标记、题干或明显结构支持该判断。

### 4. 绑定数字和表达式

数字只有在能绑定到明确对象时才能进入 `quantities`。例如：

```json
{"type": "length", "object": "AB", "value": "16", "source": "image"}
```

必须保留原始表达式字符串，例如：

```text
x + 21
2sqrt(13)
3/4
5y - 2
```

不要因为看到一个数字就猜它属于最近的线段。无法绑定时放入 `uncertain`，并说明可能的候选对象。

### 5. 建立可绘制模型

模型必须能够独立生成 redraw。绘图程序可以根据关系选择合理布局，但不得悄悄增加原 JSON 中不存在的关键对象或关系。

对于信息不足的题图，输出的是合法的 `seed scene`：

- 主要拓扑尽量保留；
- 约束关系尽量满足；
- 自由坐标只负责视觉布局；
- 不能声称已经恢复原图的精确比例或精确坐标。

## 建议 JSON 协议

每个样本输出一个独立文件 `model.json`，顶层结构如下：

```json
{
  "schema_version": "direct_geometry_agent.v2",
  "dimension": 2,
  "points": [
    {
      "id": "A",
      "label": "A",
      "visual_position": {"x": 0.2, "y": 0.8},
      "role": "vertex",
      "evidence": "observed"
    }
  ],
  "primitives": [
    {
      "id": "AB",
      "type": "segment",
      "points": ["A", "B"],
      "style": "solid",
      "evidence": "observed"
    }
  ],
  "regions": [],
  "relations": [
    {
      "type": "perpendicular",
      "objects": ["AB", "CD"],
      "evidence": "marker",
      "confidence": 0.95
    }
  ],
  "quantities": [
    {
      "type": "length",
      "object": "AB",
      "value": "16",
      "unit": null,
      "display": true,
      "evidence": "image"
    }
  ],
  "target": {
    "type": "length",
    "object": "AB",
    "symbol": "x"
  },
  "assumptions": [],
  "uncertain": []
}
```

### 字段要求

- `points`：所有可见端点、顶点和交点；不能遗漏辅助线与主体线的交点。
- `primitives`：每条独立可见线或曲线只声明一次；`style` 保留实线、虚线或隐藏线。
- `regions`：区域边界按顺序声明，可包含 `holes` 和 `fill`。
- `relations`：引用已存在的对象 ID；不要使用未声明的伪线段名。
- `quantities`：数字、表达式和单位保留原文，并绑定到明确对象。
- `target`：只在题干或图片能确定时填写；否则使用 `unknown`。
- `assumptions`：记录为了绘制 seed scene 而补充的自由布局假设。
- `uncertain`：记录无法确认的对象、关系、数字归属或图形类型。

## 绘制要求

每个样本目录应包含：

```text
images/<sample_id>/input.png
images/<sample_id>/redraw.png
json/<sample_id>.model.json
json/<sample_id>.result.json
```

redraw 必须满足：

- 具有与原图相同的主要对象数量和拓扑；
- 主要点名和交点位置关系正确；
- 线段、直线、射线、圆和弧的类型正确；
- 虚线、延长线、直角、平行、等长和阴影等可见标记尽量保留；
- 数值只绘制在对应对象附近；
- 不把未确定的数学结论伪装成已知事实。

绘制阶段可以对布局做归一化，但不要强行追随原图的像素倾斜。几何结构和约束比像素级复制更重要。

## 评估方式

每张图单独记录以下状态，不要合并成一个“成功/失败”：

```text
payload_valid
objects_complete
topology_complete
relations_complete
quantities_bound
target_recovered
seed_drawable
constraint_satisfied
visual_review_passed
```

其中：

- `payload_valid` 只表示 JSON 可解析；
- `seed_drawable` 只表示能画出合法图；
- `constraint_satisfied` 表示输出图满足声明的约束；
- `visual_review_passed` 才表示人工检查后，重绘图与原图的主要结构一致。

不能因为 `payload_valid=true` 或 `seed_drawable=true` 就称为完整重建。

## Contact sheet

最终生成：

```text
/data/Geosym127K/Geosym-World/artifacts/direct_agent_reconstruction/<run_id>/contact.png
```

每个 panel 必须同时显示：

- 原图；
- Agent redraw；
- sample id；
- JSON 对象数量；
- 关系数量；
- quantities 数量；
- 各阶段状态；
- 关键失败原因。

contact sheet 只用于快速审阅，不能替代逐图 JSON 和逐图 redraw。

## 本实验的判定结论

运行结束后，报告必须回答以下问题：

1. Agent 能否直接恢复主体拓扑？
2. Agent 能否恢复显式点名和交点？
3. Agent 能否正确识别线段、直线、射线、圆和弧？
4. 数字能否绑定到正确对象？
5. 平行、垂直、相切、中点和等长标记是否进入模型？
6. 只给结构约束时，是否能生成合法 seed scene？
7. 哪些失败来自视觉识别，哪些失败来自模型协议，哪些失败来自绘图器？

结论必须基于 contact sheet、逐图 JSON 和逐图 redraw，不得只根据 API 返回成功率判断。

# 最终版：开放式能力探针

> 本节覆盖前文所有具体流程、字段、阶段和评估规则。把本文交给新 Agent 时，只使用本节内容。

## 只给 Agent 一个任务

请处理下面目录中的 20 张几何题图：

```text
/data/Geosym127K/Geosym-World/artifacts/parser/evaluations/real_multisource_tangent_v1_20260928/run_skeleton_replay_v1_20260930/json
```

每个 JSON 的 `parser_input.image` 是原图，`parser_input.question` 是可能存在的题干。

请只根据原图和题干，尽可能把每张图片重建成数学模型，并根据你的模型重新绘制图片。每张图输出数学模型 JSON 和重绘图，最后输出一个能同时展示 20 张原图与重绘图的 `contact.png`。

## 不要预设方法

这是为了观察 Agent 自身能力的实验，不是 Parser 开发任务。不要先设计 pipeline，也不要套用任何预设的解析流程。

以下内容全部由 Agent 自己决定：

- 是否调用 VLM、OCR、OpenCV 或几何库；
- 是否通过视觉推理直接手工建立模型；
- 如何识别点、交点、线段、直线、射线、圆、弧、区域和辅助线；
- 如何处理没有字母的点；
- 如何绑定数字、表达式和题干条件；
- 如何选择坐标、约束和数学表示；
- 如何处理信息不足和多个可能解释；
- 如何把数学模型画回图片；
- 是否保留多个候选模型或多次尝试。

可以使用任何有效工具，也可以临时编写代码。不要为了兼容当前仓库而牺牲你认为更合理的表示。

## 输入隔离

不要读取或使用：

- 现有 Parser 源代码、prompt、hypothesis、admission 或 diagnosis；
- formal state、scene metadata、ground truth、生成参数；
- 以前的 redraw、旧模型或其他 Agent 的分析；
- 针对某个测试样本写好的对象映射和特殊规则。

不要修改正式 Parser。临时文件写入 `/data/Geosym127K/tmp`，实验产物写入：

```text
/data/Geosym127K/Geosym-World/artifacts/direct_agent_reconstruction/<run_id>
```

## 最终产物

每张图至少有：

- 一个表达实际几何理解的 JSON 数学模型；
- 一张根据该模型重新画出的 `redraw.png`；
- 一份能和原图并排比较的结果记录。

最终必须有：

```text
/data/Geosym127K/Geosym-World/artifacts/direct_agent_reconstruction/<run_id>/contact.png
```

JSON 不要求遵循预先规定的 schema，但必须足够表达 Agent 认为图中存在的几何对象、关系、数量、目标和不确定性，并且能够支持 redraw。

## 复盘要求

完成后只报告真实观察到的结果：

- 哪些图基本重建成功；
- 哪些图只是画出了相似外形；
- 哪些可见关系、数字或标记被遗漏；
- 哪些问题来自视觉理解，哪些来自数学建模，哪些来自绘图；
- 过程中出现了哪些原先没有预想到的问题。

不要用“接口调用成功”“JSON 可解析”或“成功生成图片”代替重建质量判断。这个实验的目的就是让 Agent 自由尝试，从结果中发现当前设计没有考虑到的问题。
