# 几何 Parser：别人如何定义，以及我们应如何定位

日期：2026-09-09。范围：扩展阅读几何题图解析、图文形式化、图到代码和感知评测工作。本文区分论文原意和本项目的设计判断，没有进行模型复现。

后续整合：参数化 CAD、约束重建与合法再生成的补充调研，以及完整开发路线，见 [可验证几何解析、重建与再合成开发计划](2026-09-09_可验证几何解析重建与再合成开发计划.md)。本文保留对 Parser 狭义任务的分类；它不是对完整重建/再合成目标的缩减。

## 1. 核心结论

“把真实图片转换成结构化数据”是一个有明确先例的任务。文献中的主要分歧，是结构化到哪一层、是否结合题干，以及是否要求生成求解器可执行的表示。

对 Geosym-World，建议把产品核心定义为：**恢复图中对象、拓扑连接和标注语义，并保留其视觉来源；公开题干可进一步补充条件和目标。** 精确坐标重建、定理闭包和答案计算分别是后续能力。

扩大检索后，可以把近年的共同理解概括为：

```text
Parser = perception + cross-modal grounding + formalization
```

面向解题的系统通常再加入 solver feedback 或 executable checking。不过，没有一个本轮核验的系统完整覆盖“局部证据、互斥候选、置信度、admission、事实作用域、可执行重建和再合成”这一整套契约。现有工作证明各部件有先例，不证明把求解器接到形式化输出后就获得了忠实、可审计的 Parser。

这比把所有工作都塞进一个“从图到可执行 state”的 Parser 更容易定协议、定 GT 和诊断失败。以下分类是基于论文的归纳，不是学界统一采用的分类法。

## 2. 六种理解

| 对 Parser 的理解 | 输入与主要输出 | 代表工作 | 对我们的意义 |
| --- | --- | --- | --- |
| 视觉场景结构恢复 | 图像 -> primitive、位置、对象间关系 | PGDPNet | 真正评价点线圆及连接、文字/marker 归属 |
| 图文指代与语义理解 | 图像+文字 -> 对齐对象和条件 | G-ALIGNER、GeoS | 题干中的 AB 必须与图上的 AB 对应 |
| 图到几何命题 | 图像 -> 形式语言、基础关系集合 | Inter-GPS 的 diagram parser、Geoparsing | 核心结构可以无需精确数学坐标 |
| 给模型提供可读描述 | 图像 -> 结构/语义 clauses 或自然语言 | PGPSNet、GOLD | 结构数据可生成不同消费格式 |
| 面向求解的自动形式化 | 图文 -> solver-ready predicates，并用执行反馈修正 | AutoGPS、SD-GPS | 是 Parser 的扩展消费者，不能只用答案衡量忠实度 |
| 绘图程序重建 | 图像 -> 可执行绘图代码及重绘结果 | Geo-Code | 适合编辑、重画、辅助线操作，需另测数学语义 |

此外，GeoPQA 采用基础感知问答检验几何理解，是诊断 Parser 的补充方式；它并不要求每次输出完整结构图。

## 3. 代表工作究竟怎么理解

### 3.1 G-ALIGNER / GeoS：解析包括跨模态指代

2014 年的 G-ALIGNER 已将 diagram understanding 定义为发现视觉元素、位置、几何属性，并把它们与文字提及对齐。2015 年 GeoS 在此基础上用图文信号给逻辑命题评分，再交给求解器。后者还明确讨论了题图不按比例绘制时，视觉相符不保证命题成立。[AAAI 2014 原文](https://ojs.aaai.org/index.php/AAAI/article/view/9146)、[GeoS EMNLP 2015，第 5 节](https://aclanthology.org/D15-1171.pdf)。

本项目判断：grounding 并非附加的小功能。识别出“5”而不知道它修饰哪条边，只完成了部分解析；同样，不能把所有视觉角度近似变成精确条件。

### 3.2 PGDPNet：Parser 是特殊的场景图生成

PGDPNet 的任务定义包含 primitive 检测识别、基础关系建立、形式语言生成。对象不仅有点线圆，还包括文字与符号；输出包含位置以及 geo2geo、text2geo、sym2geo、text2sym 等关系。论文强调细长、重叠图元不适合仅靠粗检测框表达。[IJCAI 2022，第 3.1–3.2 节](https://www.ijcai.org/proceedings/2022/0228.pdf)。

本项目判断：数据结构应把 `text_7`、`marker_2` 作为有身份的对象，建立到数学对象的边。只输出“有三条边、有一个直角”，不足以支持诊断和后续执行。

### 3.3 PGPSNet：基础结构和标注语义就有价值

PGPSNet 把图描述分成 structural clauses 与 semantic clauses：前者描述线上或圆上的有序点，后者描述数值和符号关联。论文明确不追求通过几何规则提前构建全部高阶关系，而让后续模型学习几何模式与推导。[IJCAI 2023，第 1 节、第 3.2 节](https://www.ijcai.org/proceedings/2023/0376.pdf)。

本项目判断：可以先完整输出“点的顺序、线圆关联、哪些数值和符号属于哪些对象”，不必一开始识别所有相似三角形或生成面积推导。紧凑结构也能减少模型输出负担。

### 3.4 GOLD：自然语言输出背后仍有关系结构

GOLD 先建立 sym2geo 和 geo2geo 关系，再转换成自然语言交给解题模型。它还为缺少图面名称的 primitive 分配内部引用，使没有可见名称的对象也能被描述。[Findings of NAACL 2024，第 3.3–3.4 节](https://aclanthology.org/2024.findings-naacl.19.pdf)。

本项目判断：JSON、形式语言和自然语言可以是同一结构的不同导出视图。匿名交点和未标注线段应有内部 ID；不能要求所有对象先读出字母才能存在。

### 3.5 Inter-GPS / Geo-TinyLLaVA / Geoparsing：图像到形式语言

Inter-GPS 分别解析文本与题图，再将形式化条件交给符号推理。论文分别测试预测和 GT 条件，说明可以隔离 Parser 与 solver 的误差。[ACL 2021，第 5 节、第 7 节](https://aclanthology.org/2021.acl-long.528.pdf)。

Geo-TinyLLaVA 用图像与形式化描述训练 VLM；其公开摘要限定了完整点标注的输入场景，官方流程还包含检测结果合并。它支持将直接 VLM 作为对照，但不能据此假设匿名或严重缺标图已解决。[ICML 2025 AI4Math Workshop](https://icml.cc/virtual/2025/52421)、[官方代码](https://github.com/1509cxt/Geo-TinyLLaVA)。

Geoparsing 扩展到 2D/3D 统一形式描述，并把解析拆成 `point_line`、`circle`、`plane`、`solid`、`semantic` 等层级任务；点线阶段显式要求共线点顺序，semantic 阶段处理图上明确 marker，避免从外观随意补充关系。它在平面数据上报告 96.4 的聚合分数，但整图完全正确率仅为 72.8%，说明局部指标较高不等于完整 ParseGraph 可用。需要纠正容易误读的细节：其第 5 节的几何奖励，是将预测 primitive/语义类别与 GT 对照，按类别计算加权 precision；不能把它理解为仅凭几何内核就可自动验证无标注真实图。[Findings of ACL 2026](https://aclanthology.org/2026.findings-acl.1494/)、[论文 HTML](https://arxiv.org/html/2604.11600)。

它的数据生产流程也值得区分：平面标注由 GPT-5.1 形成初稿，再经过人工修正、同伴复核和专家审计；立体标注则从头人工完成。这是 assisted annotation 的先例，不等价于两位标注员在无模型锚定下独立产生 GT。

本项目判断：采用形式语言有充分先例，直接 VLM 值得比较；但监督来源、输入假设和匹配协议必须与自己的任务对齐。我们还需同时约束召回率，避免只输出容易的少量关系。

### 3.6 AutoGPS / SD-GPS：形式化要服务执行

AutoGPS 已被 ICLR 2026 接收。它先用标注模型为关键点分配标签，再结合 PGDP-Net、题干规则解析和多模态模型形成 formalization，最后用 deductive symbolic reasoning 检查一致性、完整性并提供有界修正。其 Refine@5 实际平均只执行约 1.36–1.51 次总轮次，说明“按验证反馈选择性复查”比盲目固定多轮更合理。其失败分析还有一个特别相关的例子：数字绑定及对象命名存在偏差，形式化仍然自洽，最后答案也正确；作者明确提出了形式化忠实度问题。[ICLR 2026 官方页面](https://iclr.cc/virtual/2026/poster/10009666)、[论文 HTML](https://arxiv.org/html/2505.23381)。

AutoGPS 的另一个设计风险是：验证模块会补充隐式关系。若不区分 source assertion 与 derived fact，这些关系可能反向污染 Parser 输出。另一个工程细节是，视觉模块可以为未命名关键点提供内部引用，但不应伪造原图中并不存在的可见点名。

SD-GPS 更直接地从图文输出 solver-ready predicate sequence，再用格式合法、可执行且不矛盾、能否得到金答案等信号训练。它保留 entity grounding、ambiguity type、annotation source 和 solver status，并采用 clean 到 ambiguity-heavy/cross-modal mismatch 的课程。论文同样讨论了求解失败可能来自规则覆盖或搜索限制。[SD-GPS，2026 预印本](https://arxiv.org/html/2606.27926)。

本项目判断：执行反馈可用于诊断或有边界的复查，但未解出不能直接判错，解出也不能直接判对。修改解析必须能追溯到重新检查的图片/文本证据。

### 3.7 GeoX / MMFormalizer / 自动形式化：Parser 也被理解为下游形式证明的入口

GeoX 用统一的形式化视觉-语言预训练服务几何解题；它说明“把视觉结构变成形式表示”已经成为端到端解题模型的重要中间目标，但主要指标仍面向解题，不提供完整的 evidence/conflict/admission 协议。[ICLR 2025 官方论文页](https://proceedings.iclr.cc/paper_files/paper/2025/hash/2722a0ccf6acfe3d144fdbb0dedd80b5-Abstract-Conference.html)。

MMFormalizer 把多模态形式化描述为从 visual scene graph 递归 grounding 到命题或 Lean 表达式，并要求高层抽象由视觉证据和组合依赖支撑。这与本项目的 provenance 思路接近，但其 benchmark 只有 115 个跨领域精选样例，不能当作成熟的教材几何 Parser 基线。[2026 技术报告](https://arxiv.org/html/2601.03017)。

Autoformalizing Euclidean Geometry 主要处理自然语言/形式命题到定理证明语言，并使用 theorem prover 或 SMT 补全隐式图式推理。它提醒我们 exact string match 不足以衡量语义等价，但不负责从原始 raster 发现点线、文字和 marker。[ICML 2024 官方页面](https://icml.cc/virtual/2024/poster/33614)、[论文](https://arxiv.org/abs/2405.17216)。MATP-BENCH 则用 1,056 个带 Lean、Coq、Isabelle 形式化的多模态定理评价完整证明能力，更适合作为远期下游压力测试，而不是 Parser 忠实度 GT。[MATP-BENCH](https://arxiv.org/abs/2506.06034)。

本项目判断：应允许同一 ParseGraph 编译出 solver predicate、自然语言 clause 和证明器输入，但不能倒过来用“某个证明器能跑”定义原始解析一定正确。

### 3.8 Geo-Code：从图片恢复可编辑程序

Geo-Code 把任务组织为几何建模与代码生成两个阶段，结合像素锚定和生成、渲染、检查的反馈循环。目标偏向恢复可操作的图形程序。[2026 arXiv 原文，第 4 节](https://arxiv.org/html/2602.07749)。本轮按预印本标注，其 arXiv comment 写有 ICML2026，但未据此确认正式录用。

本项目判断：它与未来图像编辑、辅助线绘制的需求有关，但作为主 Parser 目标过重。一张图可以由许多程序绘成，原作者构造顺序通常也不可从最终图片唯一恢复；应评价等价结构和可执行性，而非要求恢复唯一“原始代码”。

### 3.9 GeoPQA：先问模型有没有看见关键关系

GeoPQA 用基础几何概念和空间关系问答研究感知瓶颈，并分别处理感知训练与推理训练。[Findings of EMNLP 2025](https://aclanthology.org/2025.findings-emnlp.1400/)。

本项目判断：可用“哪些点在这条线上”“这个数字对应哪个角”等局部检查诊断错误。给定对象后的问答成功，并不证明完整对象发现与完整解析成功，因此仍需整图评分。

## 4. 用同一个例子说明边界

假设图中三角形 ABC 内画了 CD，D 位于 AB，D 处有直角符号，CD 旁写着 4；题干要求三角形 ACD 的面积。

下列是本报告自拟示例，不是某篇论文的原始 schema：

```text
视觉观测：
  一条经过 A、D、B 的笔画
  CD 笔画；D 附近的直角 marker；文字 "4"

图面结构：
  ordered_points(line_1, [A, D, B])
  endpoints(segment_CD, [C, D])
  binds(marker_1, angle_ADC)
  binds(text_1, length_CD)

图面语义候选：
  perpendicular(CD, AB), source=marker_1
  length(CD)=4, source=text_1

图文联合目标：
  target=area(triangle_ACD), source=question_span

后续可推导：
  area(ACD)=AD*CD/2
```

图面解析可以已经正确，但 AD 仍未知、题目仍欠约束。此时应把缺少条件报告给上层，而不是通过像素长度猜出 AD。

如果 D 没有点名但交点确实可见，生成匿名内部点；如果 CD 仅在题干要求后画出，则它属于待执行构造。两种情况不能都伪装成已在原图观察到的对象。

## 5. 对上一版设计的修订建议

### 5.1 将一个大 Parser 分成两个任务接口

```text
parse_diagram(image) -> DiagramParse
interpret_problem(image, question, diagram_parse?) -> ProblemParse
compile_geometry(problem_parse) -> executable subset / unsupported
derive(admitted_state) -> facts / proof / unresolved target
```

这是职责和评测边界，不强制实现成四次模型调用。图文联合 VLM 可以共享视觉编码与推理，但需要保存题干补充了什么、纠正了什么，以及纯图结果的独立评测。

主 benchmark 先明确 image-only 的图面结构提取轨道，再提供 image+question 的联合理解轨道。Target 通常属于第二轨道；若图上直接标有未知量，可在第一轨道记录未知量及绑定，但不要自动猜测题目问什么。

### 5.2 三类输出不能混成同一种关系

1. 结构：端点、交点、线上点顺序、圆上点、区域边界。
2. 标注语义：点名、数字归属、等长刻痕、直角、平行等标记。
3. 题干条件和目标：文本中声明的中点、相似、长度与待求对象。

例如 `midpoint(D,AB)` 可以由题干直接声明，也可以由两段相同刻痕与 incidence 通过定义得到。后一情况要记录编译规则/依赖，不把它写成“图片上直接写了 midpoint”。更复杂的定理推导仍留给 solver。

### 5.3 不要求模型一次输出所有证据细节

直接 VLM baseline 先输出紧凑对象和关系。程序分配稳定 ID、校验引用并保留图像级来源；可定位的框、点、局部 crop 由模型或视觉模块另行提供。

证据精度使用显式等级：`image_only`、`localized`、`bound`。缺少局部证据就保持未定位状态，不伪造 bbox 或赋予高可信 admission。这样能分别评价“关系是否读对”与“是否定位得准”，同时保持最终审计目标。

### 5.4 先确定输出和评分，再选择模型路线

上一版的直接 VLM 优先，保留为最低工程投入的 baseline 顺序，不作为它必然优于专用 Parser 的结论。正式比较至少包含：

- 直接 VLM 的 compact diagram output。
- 相同 VLM 加 OCR/primitive 候选。
- 一个可复现的公开专用几何 Parser，前提是输入与输出任务匹配。

若专用模型已经有可用 checkpoint 且集成代价更低，可以先接入它。检测器、OCR、GNN、VLM 是实现选择，不构成 Parser 的定义。

### 5.5 明确三种不同的验证依据

| 验证依据 | 使用时机 | 可支持的结论 |
| --- | --- | --- |
| 预测与人工/可信 GT 匹配 | 离线评测、监督训练 | 在标注范围内是否忠实 |
| 来源证据与规则检查 | 推理运行时 | 是否可定位、冲突、有无明确支持 |
| solver/构造执行 | 下游使用 | 是否可执行、是否能推出结论 |

Geoparsing 的 GT 奖励、AutoGPS 的形式化检查以及本项目的 state admission 并非同一个东西，不应都简称“几何 verifier”而忽略其所需输入。

## 6. 值得保留的能力，以及还不能下的结论

已有研究覆盖了对象提取、图关系、图文对齐、形式语言输出和执行反馈。不能把这些组合本身声称为全新方法。

对我们值得检验的方向，是把真实图的部分结构、匿名交点、表达式归属、阴影边界和证据来源接入统一数据契约，并明确哪些已读出、哪些待验证、哪些只是某个构造实例的性质。这是工程目标及待验证的研究方向，不是已证实的文献空白。

本轮没有足够证据说明某个现成系统已完整覆盖一般阴影布尔区域、多候选校准、动态 admission 和长期状态维护；也不能因论文未强调这些，就断言它们完全不支持。需要后续逐项目查看 schema、代码和实际样例。

## 7. 对下一步工作的影响

下一轮最有价值的交付应是一个明确的最小任务：**真实 2D 图像 -> 点线圆/弧、线上点序、交点、文字/符号绑定和直接语义**。

先用约 20 张开发图制定人工可核对的标准输出，覆盖有数字、只有点名、未命名交点、虚线、角标和阴影。然后对照直接 VLM、工具辅助和现成专用 Parser；题干联合理解与 state 编译独立记分。阴影先允许 mask/边界候选，不要求全部立刻进入 exact boolean。

完整调研条目和筛选边界见 `docs/internal/literature-search-20260909-geometry-parser/`。本轮未修改引擎代码、调用模型或启动训练。

## 8. 扩大检索后的最终定位

别人对 Parser 的理解并不完全相同，但可以按输出责任从低到高排列：

1. 感知层：找到点、线、圆、弧、文字和 marker。
2. 场景图层：恢复 incidence、顺序、连接、region boundary 和标注绑定。
3. 图文 grounding 层：把题干名称、条件、目标与图中对象对齐。
4. 形式化层：导出 clauses、predicates 或证明器语句。
5. 求解集成层：利用执行、矛盾和答案反馈复查形式化。
6. 重建层：恢复可编辑约束图或绘图程序并重绘。

Geosym-World 不应任选其中一层就把整体称为已完成。更可靠的产品边界是：Parser 负责前 3 层并产生有证据的候选结构；formalizer/compiler 负责第 4 层；verifier/admission 限制第 5 层反馈能写入什么；reconstructor 负责第 6 层。这样既兼容现有研究，也保留本项目最关键的可审计性。

## 9. 第二轮扩展：Parser 还包含哪些常被忽略的层

第二轮检索补看了通用 diagram parsing、视觉语言歧义、线稿拓扑恢复和参数化 CAD sketch inference。新增证据使“Parser 是一个图像到形式串的模型”这一说法显得过窄。更完整的定义至少包含四层，而且四层不应压成同一种边：

1. **视觉证据层**：像素、文字框、marker、局部曲线和笔画支持。
2. **感知组织层**：哪些碎片属于同一笔画、同一符号、同一局部组；遮挡前后是否仍是同一对象。
3. **结构拓扑层**：端点、交点、连接、穿越、点序、圆弧归属和区域边界。
4. **语义与任务层**：标注绑定、精确几何条件、题干指代、公共条件和 target。

这个分法不是本项目凭空提出。AI2D 将 diagram parsing 表示为 Diagram Parse Graph；AI2D-RST 随后指出，单一 DPG 容易混淆视觉 grouping、箭头/线建立的 connectivity 和全局 discourse，并将三者拆成不同图层。[AI2D，ECCV 2016](https://arxiv.org/abs/1603.07396)、[AI2D-RST，Language Resources and Evaluation](https://link.springer.com/article/10.1007/s10579-020-09517-1)。它们不是几何题 benchmark，但对“一个局部线条到底是物体、连接还是语义符号”的建模问题高度相关。

更早的 BEATRIX blackboard 系统也没有把中间识别直接当最终事实。它让文本和图片并行解析，在 `TEXT-MODEL` 与 `PICTURE-MODEL` 中保存假设，再通过匹配形成更高层的 `PROBLEM-MODEL`。该系统的图输入仍是人工界面产生的中性图元，不是现代 raster detector，因此只能作为表示与控制流先例，不能当视觉基线。[AAAI 1990 系统说明](https://www.cs.utexas.edu/~novak/aaai90.html)。

视觉语言研究还明确区分三种歧义：**attachment**，例如文字或 marker 应绑定谁；**segmentation**，例如一条笔画是否包含可单独引用的子线段；**occlusion**，例如交叉处是连通、穿越还是遮挡。这正对应当前题图中的点名冲突、共线子段、虚线交点和复杂 junction。[IEEE Visual Languages 1999](https://ieeexplore.ieee.org/document/795889/)。线稿矢量化工作进一步表明，junction 不能只靠局部 Hough 片段处理；应先恢复全局/局部拓扑，再拟合曲线。[Pacific Graphics 2019](https://diglib.eg.org/items/447958d5-c239-4214-b341-1cf1ad5b6994)。

### 9.1 CAD 路线对“可执行 Parser”的不同理解

SketchGraphs、Vitruvion、DAVINCI 和 UniSketch 把目标定义为参数化 primitive 与约束图。输出可以直接交给约束求解器编辑或重放；这比只输出自然语言描述更接近 Geosym-World 的 executable state。[SketchGraphs](https://arxiv.org/abs/2007.08506)、[Vitruvion，ICLR 2022](https://arxiv.org/abs/2109.14124)、[DAVINCI，BMVC 2024](https://bmvc2024.org/proceedings/486/)、[UniSketch，AAAI 2026](https://ojs.aaai.org/index.php/AAAI/article/view/39525)。

但 CAD 数据中的 constraint 通常代表设计者意图，不一定在 raster 中有可见 marker；教材题图中的精确关系则必须由题干、marker 或明确协议支持。因此 CAD 路线适合借用以下能力，而不能直接把 constraint label 当真实题图可见真值：

- primitive 与 constraint 使用稳定引用的图结构；
- constraint 作用到整条 primitive 或 start/end/mid 等 sub-reference；
- 几何保持变换用于数据增强；
- 输出可由约束求解器检查并重新渲染。

DAVINCI 采用单阶段联合预测 primitive 与 constraint，以减少级联误差。这说明“模型内部联合预测”和“系统外部保持分层、可审计输出”并不冲突。Geosym-World 可以让 VLM 或专用网络联合提出候选，但仍需将证据、分组、拓扑和精确语义分别落盘。

PICASSO 使用可微渲染提供 image-level self-supervision，说明已有 renderer 可以用于预训练和几何参数拟合。[WACV 2025](https://openaccess.thecvf.com/content/WACV2025/papers/Karadeniz_PICASSO_A_Feed-Forward_Framework_for_Parametric_Inference_of_CAD_Sketches_WACV_2025_paper.pdf)。但“重绘像原图”只约束外观，不足以区分相同像素下的不同点序、label attachment、精确关系或构造语义；renderer loss 只能是 proposal/parameterization 信号，不能单独完成 semantic admission。

### 9.2 通用 structured diagram benchmark 给出的评测提醒

STRUDEL 将结构图理解拆成 identification、quantification、structural analysis、image-text association 和 image-to-code，而不是用一个最终问答分数覆盖全部错误。[LREC 2026](https://aclanthology.org/2026.lrec-1.866/)。这支持 Geosym-Bench 将以下指标独立报告：

- 视觉 component 与 primitive；
- grouping 和 junction topology；
- text/marker attachment；
- exact semantic relation 与 quantity；
- whole-graph exact match；
- executable compile、redraw fidelity 和 downstream solving。

后两项不能反向替代前四项。可执行、自洽、能重绘、甚至答案正确，都可能建立在错误但碰巧可行的 ParseGraph 上。

## 10. 对 Geosym-World Parser 设计的具体修订

### 10.1 将 ParseGraph 明确为分层候选图

当前 `evidence -> object/relation -> admission` 主线是合理的，但下一版 schema 应显式表达中间视觉组织，不只在 detector metadata 中保存：

```text
RasterEvidence
  -> VisualComponent / StrokeSupport / TextRegion / MarkerRegion
  -> PerceptualGroup and JunctionHypothesis
  -> GeometryObject and TopologyEdge
  -> SemanticBinding and SourceAssertion
  -> ProblemTarget
```

`VisualComponent` 是图像中的可见成分，`GeometryObject` 是数学对象；二者允许多对多。例如一条连续笔画可支持 AB、AD、DB，一条虚线可由多个 dash component 共同支持，一个右角 marker 由两条短 stroke 组成但绑定两条 support line。

### 10.2 冲突组需要覆盖四种错误来源

- `segmentation_conflict`：一个长笔画与多个可引用子段的备选解释。
- `junction_conflict`：连接、穿越、相切、遮挡或无交点。
- `attachment_conflict`：文字、数字、角弧、刻痕或箭头的多个合法绑定。
- `semantic_conflict`：视觉近似关系、明确 marker 和题干声明之间不一致。

这些冲突在 admission 前保留 alternatives；solver 可以排除矛盾分支，但不得把“某个分支可解”当成它忠实于原图的证明。

### 10.3 模型路线改成“联合 proposal，分层验收”

首个可训练版本不必坚持纯串行 detector。更实用的比较是：

1. 直接 VLM 输出紧凑候选图；
2. VLM 加 OCR/line/circle/marker evidence；
3. joint primitive-relation set predictor；
4. 上述 proposal 统一经过 schema、pixel topology、binding、conflict 和 admission。

内部端到端联合预测可降低级联误差，外部 typed stages 则保留审计、消融和错误定位。两者不是二选一。

### 10.4 合成数据应增加反事实监督

利用现有 renderer 生成几何保持与语义改变两类配对：

- 旋转、平移、统一缩放、点名移动和线型扰动后，拓扑与约束不变；
- 保持几何位置不变，只增删一个平行 marker、直角 marker、刻痕或数字，精确 source assertion 必须相应改变；
- 保持外观接近，改变 junction 的连通/遮挡真值，专门训练 topology；
- 同一数学对象用不同 stroke fragmentation 渲染，训练 component-to-object grouping。

这比继续堆随机图片更适合区分“看起来成立”与“图中明确给定”。

## 11. 本轮后的结论

别人对 Parser 的主流理解可以归为三种输出目标：**scene/parse graph**、**formal problem description**、**executable constraint/program**。更成熟的 diagram theory 还要求把 perceptual grouping、connectivity 和 discourse 分层；老系统已经使用中间 hypothesis 与最终 problem model 的分离。

因此 Geosym-World 当前的 hypothesis、evidence、admission 方向不是孤立设计，且比只输出一个形式串更利于审计。真正需要补强的不是再造一种 DSL，而是把 `stroke/group/junction` 中间层正式化，建立分层 GT 和评测，并用反事实合成检查每条 source assertion 是否真的随证据改变。这个结论目前有充分工程先例，但尚未通过本项目真实图 benchmark 验证。
