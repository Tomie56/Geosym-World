# Parser 首轮修复后问题审计

日期：2026-09-23。范围：检查本轮 8 张重绘、冻结 VLM 原始响应、ParseGraph、候选 State、scene 和相关实现；另执行一个内存中的最小反例。未修改产品代码，未调用模型。

## 1. 结论

首轮修复确实恢复了若干线性结构和数值约束，但仍不能把 `realized` 或“所有已输出条件满足”解释为完整模型重建。新发现的首要风险是：某些 schema 接受的关系形式没有被实际检查，却仍被报告为满足。其次是目标没有进入 State、像素与数学单位混用，以及提取和物化阶段仍有信息丢失。

“VLM 已提供的信息总是足够且正确”也不成立。当前 PGDP 面积样本在模型输出阶段就有不可同时满足的条件；圆弧样本的关键信息只写在自然语言摘要中，没有转为结构化关系。

## 2. P0：最小反例复现了关系假通过

用当前正式类型构造：

```text
A = (0, 0), B = (4, 0), M = (0, -2)
segment AB
midpoint(point=M, support=AB)
```

schema 接受此图。调用 `SeedRealizer.realize_proposal()` 后，M 坐标未被调整，返回：

```text
status = realized
midpoint outcome = satisfied
geometry_state.relations = []
verification_report.valid = true
```

M 应为 (2,0)，实际连 AB 都不在。原因链：

1. `schema/parse_graph.py` 对 midpoint 没有完整约束参数形式。
2. `parser/seed_realizer.py::_relation_holds` 的 midpoint 分支只处理至少三个引用，两引用形式没有被处理，落到函数末尾的 `return True`。
3. `_state_relation_payload` 同样无法转换此形式，未向 State 写入该关系。
4. 独立 State verifier 没有收到这条关系，无法否决；质量报告又信任 satisfied outcome。

这说明“逐条有 outcome”仍不足够，必须证明每个 outcome 对应了实际支持的编译与独立核验。下一轮应首先取消未处理分支的默认成功，统一角色/参数校验，并审计关系进入 State 的覆盖情况。

代码位置：`parser/seed_realizer.py:1258`、`parser/seed_realizer.py:1354`、`parser/seed_realizer.py:610`。

## 3. P0：目标链路没有完成

8 张中有 7 张 ParseGraph 含 target，这 7 张最终 `geometry_state.target` 均为 null。

此外发现：

- 三中线题 `Find PS` 的原始 mode 为 `query`，适配器把未知 mode 默认改为 `proof`；这是语义变更，不是无损格式转换。
- 面积比 `[ACH]:[BCH]`、三角形 `ABC`、三角形 `ACF` 被保留为 unknown 占位符，虽有相关 region，但未建立正确引用。
- PGDP 面积图 target 引用已声明 region `r1`，却被审计为 unresolved。目标处理发生在区域规范化之前，引用检查只查 object IDs。
- 当前质量判断只覆盖 relations/quantities，不覆盖 target 的保存、绑定和区域/对象物化。目标不应被当成前提，但必须被保存并单独评估可用性。

因此，目前若直接把候选 State 交给求解器，会丢失“求什么”。不能仅因图可以画出来就认为数学题模型已恢复。

代码位置：`parser/openrouter.py:984`、`parser/openrouter.py:994`、`parser/seed_realizer.py:429`、`parser/pipeline.py:163`。

## 4. P1：圆图混用了像素半径与数学坐标

样本 `geometry3k_sample_c868b4771aa7c1e1`：

- 原始 VLM 输出有视觉半径 140，以及文字半径 14、弦长 22。
- ParseGraph 将视觉半径保存为 `radius_px=140`。
- 数值求解把线段调整到数学长度 CD=22；圆物化却直接把 radius_px 作为数学半径，最终 State 的圆半径仍是 140。
- 当前 AB≈14.91、AC≈14.43、AD≈13.40，但圆半径是 140，三点当然不会落在圆周上。
- VLM 的结构化关系中也没有 B、C、D 在圆上的条件；摘要虽然写了半径/弦，但实现器没有相应关系可以执行。

问题同时在量纲/属性角色和提取完整性。单独把圆缩小十倍不能构成通用修复；需要将视觉布局参数和 radius/diameter/length 等数学测量角色分开，并实现圆上点及统一尺度约束。

代码位置：`parser/openrouter.py:239`、`parser/seed_realizer.py:490`、`parser/seed_realizer.py:662`。

## 5. P1：四分之一圆的信息跨阶段丢失

样本 `mathvision_mathvision_173`：

- 原始弧 O6 有 center、start、end、radius=180；规范化时保留中心与端点，但弧分支未保存 radius。
- 物化要求 arc 引用一个 circle 对象；O6 只有 center 引用，因此未生成任何 State arc，也没有逐对象“弧未实现”报告。
- 模型摘要明确写了内圆与两条直边、外弧相切，但 relations 只给了垂直和端点在线上，缺少三条相切约束。
- Q1 将“四分之一圆半径 6”写成对象 O6 的普通 length，测量角色不明确；内圆半径目标同样被压成普通 length。

这张图需要修提取协议执行、圆弧表示与物化映射，不能只调优化器。自然语言摘要中的“看懂了”不等于结构化条件已经完整。

## 6. P1：PGDP 面积图首先是提取错误与条件矛盾

样本 `pgdp_sample_12f441c5ad16925f` 的模型输出包含：

```text
segment CE 由 C、E 定义
F 在 segment CE 上
CF 垂直 CE
CF = 4
```

C、F 都在 CE 上，CF 与 CE 共线，不可能在长度为 4 时又垂直。无需数值优化即可识别这组冲突；当前系统只是优化后报告若干 violated 条件，没有解释冲突来源。

另有两处绑定错误：模型摘要写底边 AE=21，quantities 却绑定 AB=21；原图右侧高度应从右上顶点 D 到对角线足点 F，模型绑定成了 CF。原本的外边界也被写成了经高度脚点 B 的五边形。这些错误足以导致凹折重绘，不应再笼统归咎于后端不能画图。

下一轮应将结构冲突诊断和模型字段间一致性检查作为通用能力；不针对本题偷偷改 ID 或数值。

## 7. P1：渲染尚未忠实表达 State 与来源

- 三中线和菱形的 equal_length 已在 State 中，但当前 adapter 的刻线分支主要服务 midpoint，没有通用 equal_length 分组刻线路径；三中线 scene 中 marker 数量为 0。
- 矩形的 AC/CE 直角标记实际存在，并非完全未生成。但它沿 A→C 而非 C→A 放置在角外；B 处也有同类方向问题。应从顶点指向有效边内侧，而非直接复用线对象的存储方向。
- 原图没有的平行箭头和填充被自动添加；文字给定的 RP=3.5、JP=9 被自动画上。输入数学条件与原图可见标记的来源尚未用于显示决策。
- 四分之一圆原图没有 A/B/C/K_center 这些可见标签，模型自行命名后 renderer 照样显示，内部 ID 与可见名称的边界仍不稳定。
- 辅助虚线、延长范围、匿名点和标记组未完整恢复。

还存在重复对象：矩形 AB、BC、CD 各有原线段和 polygon edge 两份；AD 有 DA、segment_A_D、polygon edge 三份。模型同一对象的身份去重与几何容差去重需要分开处理，不能简单按相近坐标合并全部点线。

代码位置：`rendering/adapter.py:930`、`rendering/adapter.py:1024`、`parser/seed_realizer.py:479`。

## 8. 指标与求解器剩余边界

- 62/67 是候选条件满足计数，不是对原图正确性的评价，其中还含端点在线上等定义性、重复性关系。
- `realized` 主要判断点位置、relations/quantities 和已生成 State 的内部验证，缺少完整对象、region、target 的物化覆盖检查。
- `openrouter.py` 对未知关系使用 `_skip`，对没有 boundary 的 region 提前过滤，这些路径未统一进入 dropped 审计；表达式区域可能在报告“未丢失”时消失。
- ordered_points 有验证分支，但当前联合数值残差没有相应完整分支；多解、区域内外侧、保持非共线等也未统一进入求解约束。
- 数值优化固定 48 次迭代，未提供足够的停止原因和冲突定位。不能把未收敛当成无解，也不能把逼近结果当成完全正确。

## 9. 建议修复顺序

1. **先修假通过：** schema 参数校验、未支持分支显式失败、编译/物化/核验逐条件对应。
2. **补完整数学任务：** target 绑定和 State 保存、对象/region/target 覆盖、未知占位符与 dropped 审计。
3. **修圆几何和模型契约：** 测量角色与单位、圆上点、圆弧与相切；让模型将关键语义写入结构字段。
4. **补结构冲突与标注：** 定位不相容的输入条件；区分原图符号、文字给定和实例性质，修正标记方向及重复对象。

先用最小独立反例与固定模型输出回归，再进行新的 VLM 实验。此轮审计没有修改现有 8 张产物，也没有修补模型的错误条件。
