## 1. 对目标的理解

目标不只是图片转 JSON，也不只是生成一个看起来相似的 SVG，而是：

```text
真实题图 / 图片与题干 / 已有标注 / 矢量图与 CAD 草图
    -> 对象、标注归属、几何关系、区域集合关系
    -> 带证据与不确定性的统一解析表示
    -> 条件接纳、约束编译、可验证几何重建
    -> 忠实重绘 / 数学规范重绘 / 合法变体与新题生成
    -> Geosym schema、数据记录、诊断与可重放轨迹
```

这里将“集合关系”明确理解为两部分：几何 incidence/topology，以及区域包含、相交、相离、差集、孔洞与分割。不能只读点线长度而忽略阴影区域，也不能只保留 mask 而丢失组成它的边界对象。

最终产品包括三个独立标记的输出模式：

| 模式 | 必须保留 | 可以改变 | 不能声称 |
| --- | --- | --- | --- |
| `source_redraw` 忠实重绘 | 可见对象、点名、标注归属、区域和视觉布局 | 抗锯齿、轻微排版清理 | 已恢复精确尺寸或唯一原始构造 |
| `semantic_redraw` 数学重绘 | 已接纳条件与拓扑，明确的原题目标 | 选取一个合法布局，纠正不按比例的形状 | 该布局的所有数值都是原题条件 |
| `resynthesis` 再合成 | 声明的结构不变量、约束、lineage | 自由参数、绘图样式，或显式生成新条件与目标 | 改了数值却仍是原题；变体彼此独立 |

部分解析是中间产物；只完成部分图结构提取，不算完成整个解析到再合成目标。反过来，无法唯一恢复坐标也不应导致正确的图结构被丢弃。

## 2. 别人对 Parser 的理解，以及我们借鉴什么

以下归类是本项目的归纳，不是学界统一分类。论文结果均未在本机复现，不据此承诺我们的精度。

| 路线与代表工作 | 论文的主要理解 | 借鉴 | 不直接照搬 |
| --- | --- | --- | --- |
| [G-ALIGNER，AAAI 2014](https://ojs.aaai.org/index.php/AAAI/article/view/9146)、[GeoS，EMNLP 2015](https://aclanthology.org/D15-1171/) | 发现视觉元素，并与文本指代、条件对齐 | 文字与对象 grounding 是核心任务 | 像素比例不直接成为精确条件 |
| [PGDPNet，IJCAI 2022](https://www.ijcai.org/proceedings/2022/228) | 图元、位置和异质关系组成的场景图 | geo2geo、text2geo、sym2geo；薄线用几何支撑而非仅 bbox | 不将检测到的所有属性都当作给定 |
| [PGPSNet，IJCAI 2023](https://www.ijcai.org/proceedings/2023/376)、[GOLD，Findings NAACL 2024](https://aclanthology.org/2024.findings-naacl.19/) | 点序、结构和标注语义，再导出 clauses/NL | 紧凑结构、匿名对象、不同导出视图 | 不在 Parser 中抢做全部定理闭包 |
| [Inter-GPS，ACL 2021](https://aclanthology.org/2021.acl-long.528/)、[Geoparsing，Findings ACL 2026](https://aclanthology.org/2026.findings-acl.1494/) | 图文到形式条件，连接下游推理 | 独立评价预测条件与 GT 条件 | Geoparsing 的 GT 类别 precision 奖励不是无 GT 的运行时验证 |
| [AutoGPS，ICLR 2026](https://iclr.cc/virtual/2026/poster/10009666)、[SD-GPS，2026 预印本](https://arxiv.org/abs/2606.27926) | 面向 solver 的自动形式化及反馈 | 执行失败定位、条件对齐审计 | 解出答案不等于忠实读图；未解出不等于解析错误 |
| [Geo-Code，2026 预印本](https://arxiv.org/abs/2602.07749) | 图片到可执行绘图程序 | 重绘、编辑、程序执行检查 | 不要求恢复不可辨识的原作者代码或构造顺序 |
| [SketchGraphs，2020](https://arxiv.org/abs/2007.08506)、[Vitruvion，ICLR 2022](https://github.com/PrincetonLIPS/vitruvion) | 参数化图元及引用图元的设计约束；包含图像条件重建方向 | 结构化数据直接导入、约束引用、参数与关系分离 | CAD 草图能力不等于教材 OCR、题干和目标解析能力 |
| [DAVINCI，2024 预印本](https://arxiv.org/abs/2410.22857) | raster CAD 草图到图元与约束，并做约束保持变换 | 比单纯 image-to-code 更贴近重建后再合成 | 不把其 CAD 数据范围外推为一般阴影题图已解决 |
| [Aligning Constraint Generation with Design Intent，ICCV 2025](https://arxiv.org/abs/2504.13178) | 用 solver 反馈改善约束生成及修改后的设计行为 | 检查欠约束、过约束、变形与稳定性 | 不为追求 fully-constrained 给欠条件数学题编造条件 |
| [Penrose，SIGGRAPH 2020](https://penrose.cs.cmu.edu/siggraph20) | 数学描述到图形，分离语义、视觉样式与布局 | 借鉴约束布局和样式分离 | 它不是输入图片的 Parser，也不必替换现有 renderer |

补充阅读表明：**最贴近完整目标的不是单篇解题论文，而是“几何题图场景图解析 + 参数约束重建 + 受约束再生成”。** 这是路线选择，不是新颖性结论。

DAVINCI 的第 3 节显式建模图元及其子引用，第 4 节通过 FreeCAD 做 constraint-preserving transformations；这提供了“解析后还能编辑和生成”的直接先例。[原文](https://arxiv.org/html/2410.22857)。但其方法并没有为本项目提供现成的题干、表达式绑定和真假事实分层。

CAD design alignment 工作强调参数变化后的关系保持。本项目另有不同要求：**一个实例碰巧等腰，不代表原图声明了等腰；题目允许自由度也不是缺陷。** 因而不采用“自动补约束直到自由度为零”作为真实题图的成功标准。[论文](https://arxiv.org/html/2504.13178)、[作者的 ICCV 2025 说明](https://www.research.autodesk.com/blog/ai-alignment-in-cad-design-teaching-machines-to-understand-design-intent-in-autoconstrain/)。

## 3. 现有能力与真实缺口

以下表格保留计划制定时的代码阅读结论。表中模块路径均相对 `Geosym-World/src/geosym_world/`；首轮实现后的变化见第 12 节。

| 当前实现 | 可以复用 | 尚需开发或防范 |
| --- | --- | --- |
| `schema/records.py`：GeometryRecord 版本 1.0 | `state=None`、hypotheses、checksum | 逐对象证据、部分图和重建产物的版本化 payload |
| `schema/state.py`：FormalGeometryState 版本 1.1 | 稳定对象引用、确定坐标、严格状态检查 | 不能承载任意欠约束图；不能给未知坐标填 0 |
| `schema/hypotheses.py` | confidence、provenance、proposed/admitted 等状态 | confidence 必须为数值，尚不是校准概率 |
| `parser/contracts.py` | 严格输入与 PROPOSED 输出 | 白名单外还要阻断文件名、SVG 源码、sidecar 和答案泄漏 |
| `parser/clean_v0.py` | 图元候选和阶段诊断 | 不能作为真实题图已经可用的证据；OCR、绑定等仍不足 |
| `parser/adapters/canonical_builder.py` | 旧模板适配经验 | 存在启发式布局和默认边长，不能做一般精确重建依据 |
| `construction/builder.py` | 现代确定性构造、交点多解、比例点、垂足、圆弧 | 缺少从无序约束到构造 DAG 的逆向规划 |
| `verifier/admission.py` | trace grounding、执行复验、原子状态转换 | 当前验证可执行 trace，不验证原图语义是否读对 |
| `solver/closure.py` | 现有关系推导、实例量值、依赖事实 | 要隔离坐标实例性质与原题逻辑蕴含 |
| `kernel/geometry2d/regions.py` | 多边形区域、孔洞、多组件和部分布尔运算 | 不是一般曲线边界 Boolean 内核；parametric 不等于 exact resolved |
| `rendering/scene.py`、`adapter.py` | 共用 scene、SVG/PNG、标注策略、区域绘制 | 忠实重绘要避免自动新增符号、命名、目标高亮 |
| `parser/verification/image_alignment.py` | 边缘重合度与距离诊断 | 当前缩放对齐和整图分数不能证明关键数字/marker 正确 |

还存在旧 `GeoSymProblemState` 与现代 `GeometryRecord/FormalGeometryState` 两套表示。新版主路径以现代契约为准；旧适配器不能因为接收字段宽松，就充当万能兼容层。每个导入格式必须显式声明损失和不支持项。

## 4. 范围与输入协议

### 4.1 分轨输入

| 协议 | 允许输入 | 首批范围 | 后续范围 |
| --- | --- | --- | --- |
| `image_only` | 解码后像素及无语义请求 ID | 印刷 2D 点线图、简单圆、符号、数字、阴影 | 扫描、拍照、缺损与复杂复合图 |
| `image_question` | 同上 + 公开题干 | 条件、对象指代、目标 | 多语言、跨图引用、复杂文字描述 |
| `native_import` | 许可允许的标注、矢量文件、CAD primitives/constraints | 一种已有标注格式；一种 2D 参数草图格式 | SVG/PDF 路径、DXF 子集、其他数据适配 |

Native importer 是同一数据基座的另一种入口，不计入图片 Parser 的 image-only 成绩。矢量导入可获得已有路径和约束，不必先栅格化再猜回来；但 SVG 的 stroke/path 本身不一定带有数学语义。

来源登记必须保存 source_id、版本、许可、文件 hash、坐标/单位、公开字段以及 GT 可用性。题干如果包含解答或答案，数据准备阶段隔离并记录；Parser 不自行读取原始记录寻找更多信息。

首版不承诺任意真实图、3D 单视图恢复、任意曲线、透视自动校正或恢复全部隐藏条件。未知类型保存证据与 `unsupported`，不得假装成功或静默降为直线。

### 4.2 数据隔离

评测 runner 只提供 opaque ID、图片字节和协议许可的文字。合成模板名、参数文件名、formal state、scene metadata、答案和构造 trace 均放 evaluator 一侧。

仅有 Python 参数白名单不构成安全隔离。若模型可用工具，必须限制其可读目录和工具输入，不能让它根据图片路径继续打开邻近 JSON/SVG；外部模型仅收到公开输入。原始和派生 ID 对照放私有 manifest。

## 5. 总体架构和表示

```text
SourceAdapter -> EvidenceBundle
                       |
                 DiagramParse + QuestionParse
                       |
                Typed ParseGraph (PROPOSED)
                       |
                EvidenceGrounder / AdmissionPolicy
                       |
              Accepted ConstraintSpec + unresolved
                    /                \
         Observed layout           ReconstructionPlanner
                |                  /              \
          source_redraw       Exact trace       Numeric witness
                                  \                /
                             VerificationReport
                                    |
                         FormalGeometryState + scope
                                    |
                       semantic_redraw / Resynthesis
```

这些是逻辑边界，不要求一次解析调用七个模型。首个 VLM baseline 可联合输出紧凑对象和关系；局部 OCR、证据定位和图优化根据实际错误再加入。

### 5.1 三种结构不能混用

1. **EvidenceBundle**：原图/题干引用、点位置、笔画支撑、文本框、marker、阴影 mask、来源 hash。像素坐标仅用于视觉 grounding。
2. **ParseGraph / ConstraintSpec**：对象身份、关系、区域集合表达、符号量和目标；允许未定位、欠约束、互斥候选。接纳前均为 hypothesis。
3. **Realization**：某个满足已接纳约束的数学实例，含坐标、自由参数、分支、构造轨迹与验证等级。用于执行和渲染，不冒充原题唯一真值。

ParseGraph 是现代 schema 的版本化解析子结构，不另建与正式对象类型重复的全套几何内核。初期将其放在 `GeometryHypothesis.payload`，记录独立 `parse_schema_version`；根 record 版本不无故升级。确需改变正式 fact 的解释时再单独提出版本迁移。

### 5.2 最小字段约定

| 内容 | 必备字段和约束 |
| --- | --- |
| 对象 | id、type、引用、visible_name/aliases、observed/introduced、evidence_refs |
| 关系 | id、predicate、typed arguments、origin、evidence_refs、dependencies、候选状态 |
| 数量 | quantity kind、对象引用、expression AST、unit、raw_text、绑定候选 |
| 区域 | boundary refs、holes/components、set expression、fill evidence、orientation |
| 目标 | kind、对象或表达式、题干 span、未知量绑定，不含 GT answer |
| 候选组 | conflict_group、成员、选择/保留理由、未消解字段 |
| 证据 | source hash、图像坐标或文本 span、定位方法、证据精度 |
| 重建 | constraint hash、参数、自由度诊断、分支、trace、scope、验证结果 |

内部 ID 与显示名字分离；匿名交点先分配 ID，不把 `intersection(line1,line2)` 当作点名画上去。同一候选内稳定引用，修订保存映射；不声称不同模型运行天然产生相同 ID。canonical serialization 对引用图规范化，不靠坐标排序把不同拓扑误合并。

`GeometryHypothesis.confidence` 保留数值契约，但必须声明 `score_kind`，例如启发式分数或模型自评。额外的 calibrated_confidence 未标定时为 unknown；不能给 raw score 换个名称就称为概率。证据精度区分 `image_only`、`localized`、`bound`，框存在不代表语义绑定正确。

### 5.3 与现有 schema 的映射

| 新解析信息 | 编译策略 |
| --- | --- |
| 已重建点、线、线段、射线、圆、弧、多边形 | 复用正式实体；坐标/半径来源写入 realization provenance |
| 共线、平行、垂直、等长、比例、相似、相切等 | 复用 relation whitelist 和 normalization；保留定义展开的依赖 |
| 线上有序点与有限可见区间 | 解析层保留完整点序，编译 incidence 和 segment；不能只剩 unordered collinear |
| 数字/根式/分式及 marker 归属 | 量值进入 quantity/relation；视觉 token 和绑定边仍留 evidence |
| 多边形、孔洞、组件、集合差集 | 支持子集映射到 Region/CompositeRegion；未支持边界保留 proposal |
| contains/disjoint/overlaps/touches 等集合关系 | 先在 typed 解析子结构验证；正式 whitelist 扩展另立契约与测试，不塞进任意 Mapping 绕检查 |
| 未知坐标、未知长度、被遮挡弧 | 不创建伪造正式对象；保留部分结构及编译缺口 |
| 文本声明但不可见的辅助对象 | 可进入条件表示，显示状态与来源不能变成“原图可见” |

## 6. Parser 的可实现设计

### 6.1 感知与结构恢复

先输出图元候选、文字/公式和符号，不要求每个像素笔画一一对应一个数学对象。整条笔画可能含 A-D-B 三个点，AB、AD、DB 是不同的数学线段。

文字识别保留原字符串、规范化表达式和绑定候选。表达式使用受限解析器/AST，禁止任意 Python eval；根号、分式、角度单位、变量和上下标单独校验。识别到 `4` 但绑定不确定时，不提前写 `length(AB)=4`。

拓扑恢复先做端点、连接点、交点、共用支撑、线上点序，再做符号归属和直接关系。直角框需关联顶点及两条具体射线；平行箭头、等长刻痕、角平分标记需要匹配组，不能把所有箭头当作方向箭头。

### 6.2 虚线、延长线和交点

把 `dash_style` 和几何类型分开：虚线可能是辅助线、隐藏边或一般画法；不凭虚线自动赋予一种数学含义。

对 2D 图中可见支撑的交会创建交点候选，包括没有点圆点和没有名字的交会。区分：有限线段内部交会、延长线交会、共线重叠区间、切触点和仅无限支撑线相交。只在实际画出/声明的延伸范围内增加可见交会。

候选 grounding 后，共用交点必须用同一正式 ID，并记录它在哪些线/弧上；渲染器不能独自创造不进入 State 的交点。3D 投影交叉、跨越符号和遮挡另处理，不能误提升为真实空间 incidence。

### 6.3 区域与集合关系

区域识别采用“填充证据 + 边界图 + 集合表达”三者关联：mask 用于定位，边界由有向线段/弧引用组成，set AST 表达 union/intersection/difference。

必须区分集合、内部和边界：两个区域内部不相交，边界仍可能共享一条边；两个圆盘可只有一个切点。面积为零不代表交集信息可以删除。CGAL 的 regularized Boolean 会消去低维特征，因此即使以后采用该类内核，接触点和共享边仍需独立拓扑记录。[CGAL 官方手册](https://doc.cgal.org/latest/Boolean_set_operations_2/index.html)。

首批精确范围为简单多边形、严格内部孔洞和多组件；圆/扇形使用已支持的参数区域。一般线弧混合布尔边界先保留结构和近似可视化，后续评估成熟 exact arrangement/Boolean 库，不自行仓促实现通用曲线求交。

### 6.4 模型路线比较，而非先锁定架构

| 候选 | 用途 | 升级依据 |
| --- | --- | --- |
| 当前 OpenCV clean baseline | 测清楚已有候选器的覆盖和错误 | 作为对照，不要求承担全部 OCR |
| 通用 VLM 直接紧凑图输出 | 最短可比较路径，处理整体语义 | 先看 binding、漏点、幻觉和成本 |
| 同一 VLM + OCR/primitive 候选 | 检验局部证据是否实际改善 | 只在对应错误明显且收益可测时保留 |
| PGDP/GOLD 等专用图解析路线 | 对象和关系的任务匹配对照 | 先核验代码、checkpoint、许可与输入范围 |
| 专用检测/关系模型训练 | 长期降低高频组件错误和推理成本 | 需要已稳定 GT、足够许可数据和可复现 baseline |

不预设多 Agent 会更强。首轮固定模型版本和预算，默认一次整图推理；局部复查作为显式配置、单独报告成本，不加入无界重试或失败时静默切换模型。具体模型、部署方式和预算在运行前确定，本轮不安装或试跑。

## 7. 从关系到可执行重建

### 7.1 先规划，后求坐标

1. 将已接纳条件转为类型化约束；保留强制条件、布局偏好、分支限制的区别。
2. 按连通分量找锚点和构造模式，优先复用 midpoint、ratio、foot、intersection、circle 等现代构造操作。
3. 为每个操作建立输入对象、前置条件、输出与依赖 DAG；检查循环依赖与欠条件。
4. 对可构造子集使用精确 SymPy 值；多解保存分支条件，不依赖求交列表顺序。
5. 非构造子集可显式选择数值约束后端生成 witness，记录 residual、初值、尺度和未验证项。
6. 复验所有强制条件、退化、拓扑及边界后，再创建相应等级的 realization。

原图最终形状通常不能唯一决定原作者构造过程。这里输出的是**一个可重放重建过程**，不伪造原始 construction history。

### 7.2 欠约束、尺度和分支

平移、旋转等规范自由度可固定为布局 gauge，不是新增原题条件。没有尺寸时，选择单位长度仅用于画图。镜像、圆交点双解、弧方向和孔洞归属是语义分支，需要视觉/文本证据或明确保留歧义。

局部 Jacobian 秩可用于数值自由度诊断，但不能当作全局唯一性证明。求解器未收敛只能记 `not_converged`，不能宣称 inconsistent；只有有证据的矛盾或证明才归为条件不相容。

数值优化采用成熟工具作为可选后端。SolveSpace 的官方说明是数值方程求解，SciPy least_squares 是局部最小二乘；两者都不自动给出原题精确证明。依赖、许可、绑定和部署成本先审计，未批准前不增加依赖。[SolveSpace](https://solvespace.com/tech.pl)、[SciPy](https://docs.scipy.org/doc/scipy/reference/generated/scipy.optimize.least_squares.html)。

### 7.3 不让一个 witness 污染原题事实

必须在执行 API 和 verifier 中区分：

- `source_assertion`：有图文来源、按 admission policy 接纳的条件。
- `entailed_fact`：从已接纳条件和规则推导，带依赖；其正确性以这些条件为前提。
- `realization_fact`：只在所选坐标实例上成立的量值或偶然关系。
- `generation_parameter`：再合成时明确选择的新值，不是从原图识别出来的值。

仅在 metadata 写 scope 不够。现有 closure 会使用坐标量值，必须新增消费侧过滤与 proof dependency 检查，阻止原题 target 的证明使用无源 witness 数值。生成新题可使用 generation_parameter，但要显式生成相应公开条件。

对含多个有效模型的原题，证明某个 target 必须基于条件蕴含；在一个布局上算对不算解决原题。数值后端产物若不能转换为可验证 exact 构造，只能标为 numeric witness，不导出 exact proof/GT。

## 8. Grounding、Admission 与验证

接纳不等于系统证明自己“看对了”。运行时可检查证据位置、类型、冲突、约束和执行；无人工/可信 GT 时，真实图语义忠实度仍有不确定性。

| 验证层 | 检查内容 | 成功能说明什么 |
| --- | --- | --- |
| Schema | 类型、ID、引用、表达式和版本 | 表示合法 |
| Evidence grounding | 点/笔画/文字/marker 绑定及文本 span | 有可检查来源；不自动保证解释唯一 |
| Semantic consistency | 同名异点、数字错绑、矛盾条件、单位 | 已发现冲突与未消解项明确 |
| Construction | 依赖、分支、退化、trace 重放 | 所选构造可执行 |
| Geometry | exact 检查或有尺度说明的数值 residual | 明确精度等级下满足已编码条件 |
| Topology/region | 点序、所有交点、孔洞/组件、共享边、面积覆盖 | 重建未悄悄改变已声明的结构 |
| Fidelity | 人工/可信 GT 与独立视觉证据比对 | 在该标注范围内忠实，而非仅自洽 |
| Export | SVG/PNG、标注可见性、公开字段、lineage | 导出与本次结构/策略一致 |

所有报告保存 checker/version、input hash、检查域、passed/failed/unknown/unsupported、误差尺度和依赖。一个总 `valid=true` 不能掩盖 fidelity 未检验或 exactness 不成立。

逐 hypothesis 或依赖闭合的候选组接纳；互相依赖的对象与关系原子提交。拒绝、abstain 保留旧 State checksum，记录原因。父候选被撤销/修订时，其依赖事实与生成产物必须失效重算。

首版接纳策略采用白名单：有明确图文证据、绑定已消解且检查通过的支持类型才可自动接纳；仅凭外观接近平行/等长、模型高自评分或 solver 恰好可解，不满足条件。接纳的 source_assertion 仍保留证据可信级别，下游证明以它为前提；真实数据进入可信 benchmark GT 还需人工审阅或已核验的结构化来源。自动接纳率与人工可信 GT 数量分别统计。

原有 `HypothesisAdmission` 继续负责 executable trace 事务，新 semantic grounding/admission 在它之前做证据与条件检查。不得把任意未验证 ParseGraph 塞进 trace payload 后借一次执行成功全部接纳。

建议错误分类：input_invalid、reference_unresolved、ocr_ambiguous、binding_ambiguous、unsupported_geometry、condition_conflict、underconstrained、branch_ambiguous、construction_degenerate、numeric_unstable、topology_changed、fidelity_mismatch、visibility_mismatch。保留现有基础异常类别，并以结构化诊断 code 细分，不建立第二套不兼容异常层级。

## 9. 重绘与再合成

### 9.1 保持渲染单一路径

最终都落到现有 RenderScene 和同一 SVG/PNG 渲染链。忠实重绘使用 observed layout 到 scene 的明确投影；数学重绘使用验证后的 FormalGeometryState 到 scene。前者不是绕过验证的正式数学 State。

增加 source visibility/annotation projection：仅画原图可见名字、明确给定数字和实际 marker；匿名内部点、求解辅助对象、自动直角/平行判断、target 高亮不默认显示。review 模式可以展示，但必须与 benchmark 图片分开。

现有 `RenderLabel` 没有 metadata 字段，证据与对象对应先由统一 sidecar/scene metadata 保存，不能在设计中假设该字段已存在。数字排版复用数学表达式渲染，不把 `sqrt(13)/3` 当普通文本压在图上。

忠实布局评价需处理裁剪、缩放和旋转，但配准不能任意非刚性扭曲掩盖读图错误。数学重绘主要检查语义与拓扑，不能强求与不按比例原图的每个像素一致。

### 9.2 三种增强，分别声明不变量

| 增强 | 可以保持 | 必须处理 |
| --- | --- | --- |
| 样式/扫描扰动 | formal state、题目条件 | 字体/线型/噪声改变后可读性，图像坐标证据随变换更新 |
| 同题合法变形 | 原 givens、原 target 含义 | 在自由度内变形，保持点序、交点分支、区域和退化余量 |
| 新题参数化生成 | 声明的结构族 | 重新生成数量、题干、target、答案、推导与公开标注 |

平移/旋转通常保持距离角度；统一缩放需同步长度和面积尺度；非均匀仿射不能用于保持圆与角度的数学增强。照片透视变换可以作为感知扰动，不得把变换后的像素几何直接作为新的欧氏真值。

参数化不能只是随机挪点。每次生成先检查约束可满足性、非退化余量、交点数/分支、点序、区域组件和孔洞，再执行。只有显式允许拓扑变化的新任务族才可改变这些条件。

### 9.3 目标驱动合成与可重放

重建出的约束族进入已有 synthesis task graph：先选 target 和证明/计算骨架，再反向确定必须公开的条件与辅助构造。每个新增对象要被后续操作、公开条件或 target derivation 使用。

5-6 步复杂任务按有效依赖深度、分支和推导难度验收，不把新增无关点凑成复杂度。生成 supervision 是本次构造/推导路径；多合法解法分别记录，不能把同一拓扑镜像当作另一种证明。

每个记录包含 image、question、public givens、formal state、trace、facts、derivation、target、verification、diagnostic axes 和 lineage。额外记录 source/license、解析候选版本、admission policy、realization 分支、增强类型、seed、拒绝原因、renderer 版本与所有 checksum。

source_redraw、semantic_redraw 和新题记录分别标识。无法验证的真实图不能混入 verified benchmark GT；其 proposal 可作为待审阅数据保存。

## 10. 四个端到端验收例子

### A. 不按比例三角形与垂足

原图：D 在 AB 上，CD 垂直 AB，CD 标 4；题目求 ACD 面积，但没有 AD。

正确解析保留 A-D-B 点序、直角 marker 和 `length(CD)=4`。可忠实重绘，也可令 D=(0,0)、C=(0,4)、A=(-a,0) 生成某个数学布局，但 a 是自由参数。原题只能保留 `area(ACD)=2a`，不能读像素补答案。

新题生成若选 a=3，须显式公开 AD=3，再生成答案 6；记录它是新题，不是原图解析出的数据。

### B. 矩形内两个孔洞

若图文明确外框是 12×7 矩形、两个内框是互不相交且严格内部的 2×2 正方形，则结构为 `outer \ (hole_left union hole_right)`，阴影面积为 76。

孔洞四个角和外框四个角均有内部 ID，名字只按原图显示。不能让 I/J 等点名与 2/7 的数字相互错绑。若矩形/正方形仅仅“看起来像”而无题干或符号支持，相关精确类型仍是 proposal，不能直接把 76 当可信 GT。

验收同时检查 2 个孔、1 个区域组件、阴影 mask、边界归属、面积和无标签遮挡。孔洞接触外边界的变体不能仍沿用“严格内部孔洞”的证书。

### C. 两圆与阴影透镜

两圆有两个交点 P/Q，透镜由两个定向圆弧组成。必须保留两交点、圆引用、弧起终点、方向和区域内部侧；只记录“两个圆相交”不足以重绘阴影。

图结构和弧界 mask 可先正确导出；exact 透镜面积只有在半径、圆心距和曲线内核覆盖时才计算。相切时交点合并、区域面积为零，属于拓扑事件，必须改变结构状态，不能继续输出两点 lens。

### D. 参数草图导入与保持约束的再生成

从许可允许的 CAD 草图导入线段、端点重合、平行、垂直和显式尺寸。先映射对象及单位，再编译矩形构造；修改宽度时保持所声明的关系并同步标注。

CAD 原生约束与程序测得的偶然等长分别标记；source native_import 的结果单列，不参与 image-only 竞赛。若另外栅格化成图片做 Parser 测试，只把像素交给 Parser，原生约束交给 evaluator。

## 11. Benchmark 与验收协议

### 11.1 先建立可信小集合

建议初始投入约 20 张真实开发图定义标注规范，再组成 60 张真实图和 120 张合成图的首轮集合。20 张属于这 60 张，不重复计算。数量是工作量规划，不是现有标注量；来源和许可先确认。

首轮真实图至少覆盖点名、匿名交点、角标/刻痕、表达式绑定、虚线延长线、圆弧及阴影，包含欠约束和不按比例图。人工双人独立标注后裁决；没有第二位标注者时明确降低 GT 可信等级，不把模型自检称为人工复核。

合成分 clean 和 perturbation；后续新增非本引擎风格和更多真实来源。按原题/source family/base spec 分组 split，重绘、裁剪、同构结构 mutation、CAD 同源变体不能跨 split。与公开训练数据重叠只做可查范围内审计，不能保证商业模型从未见过图片。

### 11.2 分层评分，不能只比较数量和答案

| 层 | 指标及关键切片 |
| --- | --- |
| 对象 | 类型+位置/支撑匹配后的 precision/recall/F1，匿名点和薄线单列 |
| 拓扑 | 端点、交点、点序、圆弧关联、重叠/切触；保留参数化不变的等价匹配 |
| 标注 | OCR/表达式 exact match、符号类别、text/marker-to-object binding |
| 条件/目标 | 规范化谓词及参数匹配；数值、单位、target 指代，不比较 GT answer 代替目标 |
| 区域 | mask IoU + boundary relation + 孔洞/组件/接触类型，不仅面积相同 |
| 不确定性 | 覆盖率与选择性风险，拒绝/abstain/unknown 分母明确；校准后才报 ECE 等 |
| 接纳 | false admission、漏接纳、无证据精确关系、依赖 scope 越界 |
| 重建 | exact/numeric/partial/unsupported 分布、约束满足、trace replay、分支拓扑 |
| 再合成 | 不变量保持、有效 target、无 dead ops、谱系 split 泄漏、有效样本率 |
| 成本 | 每图调用数、输入输出 token、延迟、失败原因、人工复核耗时 |

对象匹配使用一对一几何/类型匹配与已核验名称，关系评价随后进行，不能拿 GT 关系反过来挑最有利的对象映射。名称相同但位置/绑定错也要扣分；评估对点重命名的结构等价性时单独报告该轨道。

设 GT ParseGraph 输入的重建上限对照，预测 ParseGraph 输入的端到端对照，GT scene 输入的纯渲染对照，分别定位 perception/compiler/renderer 的失败。

### 11.3 提议的发布门槛

以下是待批准目标，不是已取得结果。P1 冻结标注后再确定各指标阈值，禁止看测试结果后调整测试集或指标。

- 工程硬门槛：隔离/引用/拒绝不改状态/scope/trace/manifest 的确定性测试全部通过；所有 verified 导出具有完整证书。
- 支持范围内 clean 初始目标：拓扑 F1、标注绑定准确率各不低于 95%，同时报召回、分类型结果及样本数；不合并真实和合成分数。
- 接纳安全性：在人工审计的已接纳命题上报告错误率及置信区间。小集合“零错误”只能说该集合未发现错误，不能推断真实错误率低于 1%。
- 重建和再合成：可编译率/可生成率要与成功样本的正确率一起报告，避免通过大量 abstain 美化结果。
- 合成回归沿用需求：固定版本/seed 的 500 条严格计数、ID 唯一、文件匹配、全量 target 验证；非预期退化拒绝率低于 5%，分母为实际尝试候选并单列合法过滤。需另行批准运行。
- 真实开放域不设置未经测量的高精度承诺；低覆盖则发布受限范围和失败切片，不宣称通用 Parser。

## 13. 代码归属、测试与 Git

此处是未来改动归属，不创建空目录或占位 API。

| 位置，相对 `src/geosym_world/` | 职责 |
| --- | --- |
| `schema/` | 解析子结构、类型、版本、事实作用域和序列化契约 |
| `parser/` | 数据到候选图、文字/符号 grounding、来源适配、重建编译组织 |

测试重点包括：未知字段拒绝；匿名交点不丢；名字别名不覆盖对象；数字位置相近但绑定不同；度/弧度和根式等价；弧双解；重叠区间；孔洞触界；欠约束不填默认真值；拒绝 checksum 不变；witness fact 不能证明原题；SVG/PNG 标注一致；失败候选不混入 verified GT；同源 mutation 不跨 split。

每包先最近测试，再完整 Geosym-World 测试。大型合成/模型 benchmark 单独说明配置、资源、产物和判定标准，经批准执行。不修改 GeoClaw，依赖方向仍为 GeoClaw -> Geosym-World。

开始每包先检查 Git 根、状态和 diff，兼容现有未提交改动。按 schema、安全/评测、Parser、重建、渲染/合成等目的组织可独立验证的变更，只有用户要求才 commit。本轮不提交代码，也不移动/删除旧代码。

## 14. 实验资源、产物与复现

首轮不训练。设计完成后先确认可调用的模型、许可、联网与隐私政策，再为 P2 给出模型调用次数上限、每图 token 上限和总费用上限。工具辅助路线使用同等总预算另做对照；不能只报更高分不报成本。

建议产物布局，均为未来路径约定：

```text
Geosym-World/artifacts/parser/<run_id>/
  manifest.json
  predictions.jsonl
  evidence/
  reconstructions/
  renders/source_redraw/
  renders/semantic_redraw/
  diagnostics/
Geosym-World/artifacts/generated/<run_id>/
  records.jsonl
  manifest.json
  images/
```

manifest 记录 commit 与 dirty diff hash、环境锁定信息、输入版本、模型/checkpoint/prompt/策略版本、seed、命令、外部请求 ID、输出 hash 和许可。图像证据与原始数据按来源许可控制；不能因为代码公开就重新分发所有图片。

SketchGraphs 可提供真实参数草图约束，但原始设计的权利与代码许可不是一回事；选样和再发布前核查源数据条款。PGPS/PGDP 等数据也要分别核对下载、研究使用和再分发条件，不做无许可批量搬运。[SketchGraphs 官方仓库](https://github.com/PrincetonLIPS/SketchGraphs)、[PGPS9K 官方入口](https://nlpr.ia.ac.cn/databases/CASIA-PGPS9K/)。

临时分析放工作区 `tmp/`；运行图像放各自 artifacts，不能写根分区的历史 `/tmp/geosym*` 目录。本计划不创建活动项目副本或下载大型数据。

## 15. 最终决策与明确未完成项

建议采用：**有证据的图结构作为 Parser 核心，约束重建作为独立编译过程，现有几何引擎作为分级验证和再合成后端。** 不强迫感知模型直接写完整 State，也不让只会重画的代码模型代替几何语义。

近期优先级是 P0/P1：先把解析输出、人工 GT、事实 scope 和评价协议定清楚；随后做最短 baseline，并行用 GT 图验证重建器。这样能分别判断“没看对”和“看对但引擎接不进去”。

首轮实现已完成 typed ParseGraph、事实 scope、来源隔离、合成 typed GT、结构评测、OpenCV typed baseline、保守点名/目标 grounding、evidence-gated admission、分级重建、三类输出接口、受限 exact similarity、人工标注/独立复核/裁决契约和批处理 manifest，并通过当前 Geosym-World 全量测试。尚未完成 Parser 模型比较、许可真实数据的实际人工标注、一般非线性重建、一般分支搜索、native importer、曲线区域逆向重建和一般非刚性约束保持再合成。论文可借鉴不等于可直接运行，公开 checkpoint、代码兼容性和精度均需实际验证。
