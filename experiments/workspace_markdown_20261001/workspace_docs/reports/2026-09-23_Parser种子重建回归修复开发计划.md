# Parser 种子重建回归修复开发计划

日期：2026-09-23  
状态：首轮已实施候选入口、部分布局/数值处理和质量指标修复；完整计划尚未完成。实际结果见同目录 `2026-09-23_Parser种子重建首轮修复结果.md`。  
开发仓库：`/data/Geosym127K/Geosym-World`。

## 1. 目标与本轮边界

恢复并稳定以下通用能力：从图片与有限文本提取几何假设，保留完整结构和可用数值，调用现有引擎生成满足这些假设的候选几何实例，并从 Geometry State 重绘。

信息不足以唯一确定图形时，可以输出一个合法种子；信息不足以构造时，保留结构表示和明确诊断。不得以完整精确重建为所有输入的前置要求，也不得靠删除条件制造成功。

本计划延续 `2026-09-20_通用几何Parser开发计划.md` 与 `2026-09-21_Agent重建复盘与VLM数据引擎协同计划.md`，明确修订前者第 4.1 节的执行边界：**未经事实准入的假设可以在隔离的候选实例中接受数学可满足性检验，但不得因此写入可信的原题事实。** 事实准入仍然保留，不能用 proposal 入口绕过其权限。

本轮优先修复二维直线结构、已有数值构造和主流程的信息丢失。保留现有圆、弧、区域能力并核对回归，未实现的组合明确返回不支持。暂不扩展高级 3D、不重写渲染器、不引入新模型框架、不开展大规模在线评测。

## 3. 目标流程与信任边界

```text
图片 + 可选题目文本
        |
        v
VLM 提取 -> ParseGraph：对象、拓扑、关系、数量、目标、证据
        |
        v
引用绑定 / 类型校验 / 条件分类 / 显式冲突诊断
        |
        +-> 事实准入：保留完整审查记录，决定哪些条件可被可信使用
        |
        v
选择一组明确的候选假设 -> 构造依赖 / 约束编译
        |
        v
SeedRealizer：精确构造优先，必要时联合数值求解
        |
        v
独立 verifier：核对所选假设、数量、对象覆盖和非退化
        |
        v
候选 Geometry State -> 正式 renderer -> 重绘与审阅
```

OpenCV/OCR 是可选证据模块，服务于局部绑定、端点吸附和差异诊断。它们不再默认先删除候选结构，再让实现器处理残缺图。

必须区分四类内容：

1. **原图解释假设：** VLM 提取内容，携带 confidence、来源与证据；高置信度不等于事实。
2. **候选实例：** 假设成立条件下构造出的坐标与对象。构造成功仅证明本实例满足这些条件。
3. **实例选择与偶然性质：** 为画图选定的自由参数、规范坐标，以及实例恰好具备的额外关系，不能回流为原题条件。
4. **已准入事实：** 经证据与策略审查允许使用的条件；由其推导的事实保留依赖。候选实例验证不自动完成这一步。

复用 Geometry State 表达实例；候选状态在结果中必须有明确用途、假设 ID 与来源映射，不能和可信原题状态混用。优先复用现有字段，确有缺口时最小扩展，不建立第二套几何 schema。

## 4. 开发规则

- 按关系与约束类型实现，不按数据集、样本 ID、固定点名或整张图模板分支。
- 一份 ParseGraph、一条明确主流程，复用现有内核、构造器、求解器和 verifier；不恢复整套旧 hybrid 系统。
- 不为通过样例添加猜测、自动重试、静默舍弃约束或隐式降级。部分输出必须显式报告缺失项。
- 固定原始 VLM 响应回放，先修后端；此阶段不改提示词、不更换模型、不重新采样掩盖回归。
- 区分题目已知条件、待求量、待证明目标和外观猜测；目标不能被当成求解前提。
- 每次修复同时验证一个不同命名、布局或结构组合的例子；原 8 张是回归集，不是泛化能力的全部依据。
- 不执行模型生成的 Python；数学表达式沿用受限解析和符号计算能力。
- 原始响应、人工参考与运行状态分开保存；人工修正后的结果必须标记，不能冒充自动输出。
- 保留当前未提交改动，不 reset、checkout、clean；只在用户明确要求时提交。

## 5. 实施阶段

### P0：冻结可复现的对照输入与判定口径

工作：

- 为旧矩形结果、现有 8 张多源样本和人工参考建立索引，记录原图、文本、原始响应、协议版本、模型及提示词版本。
- 分开准备两层输入：固定 VLM 输出用于定位编译与后端问题；人工确认的最小 ParseGraph 用于独立检验几何实现器。
- 记录当前代码文件哈希及相关差异，不能只记录相同的 Git HEAD；不打包 `.env` 或凭据。
- 冻结每个样本要保留的对象、拓扑、显式数值、符号和目标，记录人工不确定项。
- 先建立“条件覆盖不足不能整体成功”的负例，避免后续修复只提高出图数量。

验收：同一批已保存输入可以离线重复执行；代码版本、输入来源和人工介入程度可追溯。此阶段不新增在线模型请求。

### P1：修复主入口，恢复候选种子路径

主要位置：`parser/pipeline.py`、`parser/seed_realizer.py`、`verifier/parse_graph.py`。

工作：

- 复用 `realize_proposal()` 与 `_realize_graph()`，让完整、类型合法的候选语义图进入种子构造；同时保留独立的 admission 报告。
- 所选假设清单必须显式，互斥候选不能同时成立；歧义无法选择时返回未决，不私自挑选最容易出图的解释。
- 非法引用、非法类型与明确冲突不能通过换入口绕过。仅证据不足的假设可被隔离地尝试，但不得写入可信原题 facts。
- 像素不匹配作为诊断记录；确认几何条件矛盾与“像素没检出”使用不同错误类型。
- 结果保存完整候选图、事实准入结论、所选假设和实现报告，避免复制两套管线。

验收：证据未准入不再直接等于不能生成候选种子；构造成功不会提升事实可信级别；非法输入仍明确失败；旧矩形路径可在固定输入上得到有解释的结果。

### P2：绑定对象与条件，消除静默丢失

主要位置：`schema/parse_graph.py`、`parser/openrouter.py`、`parser/prediction.py`。

工作：

- 统一稳定 ID、可见名称与对象引用。端点明确且存在时，可建立被数量或关系引用的子线段，并保留其来源；端点不明确时记录未解析引用。
- 同一数学对象去重，保留完整线段和子线段的关联，不把未知对象占位符算成成功绑定。
- 保留无名对象、多子图作用域、圆弧及区域引用；不依靠两字符字符串猜线段端点。
- 数量保留原文、表达式、单位、作用对象和角色；单位一致化必须有依据，符号值不强行转浮点。
- 所有不支持的关系、目标和区域表达式进入诊断，不默默跳过；模型格式转换仅采用明确、无损的映射。
- 每个输入条件有唯一处理记录，能追踪到编译约束、验证结果或具体阻塞原因。

验收：原有关系、数量、目标均可逐条追踪；不存在丢失条件后完整性指标仍通过的情况；ID 重命名和对象顺序变化不改变数学含义。

### P3：修复约束实现与布局保持

主要位置：`parser/constraint_completion.py`、`parser/seed_realizer.py`，必要时复用或补充正式 kernel/solver/verifier。

工作顺序：

1. 保留 VLM/观察布局作为初始化与分支线索，解除“局部约束不满足就丢弃全图坐标”的行为。
2. 复用中点、比例点、垂足、交点等精确构造；矩形等复合关系展开成可组合的基本条件。现有精确矩形能力按数学适用条件复用，不按样本触发。
3. 联合处理共线、点序、点在线段/射线/直线上、平行、垂直、等长、比例及已知长度。区分不同对象的参数域。
4. 有数值时固定合法尺度；无数值时允许选择自由参数。像素距离不自动变成真实长度。
5. 耦合约束确需数值求解时，显式设置计算预算、尺度化容差与残差报告。布局只是软偏好，不能抵消数学约束违反。
6. 保留镜像、多解、内外侧和非退化条件。未收敛、预算耗尽、关系不支持与已证矛盾分开记录；单次数值失败不宣称不可满足。
7. 独立 verifier 从最终坐标重算全部所选约束，再输出候选 State。圆、弧、区域沿用同一覆盖审计，未支持条件不得被忽略。

验收：确定性测试中的三中点/共点、矩形/外接垂线/已知长度、垂足/面积分割等组合满足全部给定约束；改变尺度、点名、方向后仍成立；冲突和退化负例不误报成功。只有题目给出或有证据支持的条件才进入约束，不能从“看起来像”补充条件。

### P4：修复质量报告与状态重绘

主要位置：`parser/pipeline.py`、`verifier/pixel_topology.py`、现有 rendering adapter 和 CLI。

沿用六个评价维度，但修正语义和分母：

| 维度 | 修复后的判定 |
|---|---|
| `payload_compiled` | 响应已解码并编译；未支持内容有记录，不能代表内容完整 |
| `semantic_graph_complete` | 区分图内引用完整与相对原图的语义覆盖；后者没有独立参考时为 unknown，不能仅用“无编译报错”推断 |
| `seed_realized` | 明确所选假设下生成候选 State 和可重绘 scene；不等同完整满足条件 |
| `constraint_satisfied` | 所有所选约束均有独立验证结果，包含数量；任何未处理必需条件阻止整体通过，并报告相对完整输入的覆盖 |
| `pixel_topology_passed` | 区分输入侧定位检查与最终重绘侧检查，分别给出作用对象；未检查为 unknown，不冒充通过 |
| `source_reconstruction_passed` | 需要独立参考或明确人工审阅，涵盖原图必要对象、拓扑、标记、数值和目标；没有依据为 unknown，不由前几个布尔值自动合取产生 |

如现有协议只允许 bool，做最小版本化修改，明确通过/失败/未评估，不把 unknown 编成 false 后混入失败率。同步调整 CLI 汇总和协议文档。

重绘只从候选 Geometry State 产生。源图可见数值和符号按绑定证据绘制；题目文字给定可以参与约束，但不必全部加到图上。自由参数、求出的目标值、自动产生的内部点不默认展示成原图标注。部分结果显式标注缺失，失败样本保留诊断图，不伪造有效 redraw。

验收：只满足 1/7 条关系的样本不会被认定完整恢复；量值未处理不会报约束全满足；输入侧像素检查不能认证最终重建；缺少原图参考时不报告未经评估的成功率。

### P5：离线回归、独立审阅与有限在线验证

工作：

- 先运行最近的单元测试，再运行 Geosym-World 全量测试，使用 `/data/miniconda3/envs/geosym/bin/python`；缺失依赖先说明，不静默安装或换环境。
- 固定原 8 张 VLM 输出，生成修复前后对照，逐条核对条件流向及最终 State；人工参考只用于评测。
- 增加独立的最小关系组合与负例，覆盖无数字、非比例布局、无名点、多子图重名、未知表达式、冲突、未支持圆弧等。不得把同一母图的多个变体包装成多个独立真实样本。
- 在已有本地图像中冻结一小组未用于修复的审阅样本；在线验证前另列数量、模型、请求上限、预计成本、产物和标准。默认每图一次请求，不重试，不因结果差重复抽取。
- image-only 与 image+text 如需比较，使用相同图片配对，分别统计提取和后端结果，避免与离线回放混算。

验收分两层：确定性正例满足全部必要条件、负例无假成功；真实图片逐图给出通过/部分/失败/未评估及原因，实测报告，不预先承诺成功率。新版本不得仅用出图数量超过旧版作为交付依据。

## 6. 产物与审阅方式

修复验证统一放在 `Geosym-World/artifacts/parser/evaluations/seed_repair_<run_id>/`：

```text
manifest.json          输入哈希、代码差异标识、配置、命令、环境、模型调用信息
summary.json           全部样本计数、分阶段结果、覆盖率、失败类型、耗时与成本
review.md              中文逐图结论，区分自动结果和人工参考
json/<sample>.json     ParseGraph、绑定、准入、所选假设、State、逐条件验证
images/<sample>/       input.png、redraw.png（若有）、review.png
debug/                 仅按需保存调试信息；固定原始响应以索引和哈希引用
```

审阅页按“原图—旧结果—新结果—遗漏/违反条件”展示；旧结果的语义类型必须注明，不能拿 observation redraw 充当可信几何状态。保留必要的历史基线，暂不清理用于对照的产物。

不产生新的平行状态格式，不重复存放每阶段整份 JSON；临时检查脚本在工作区 `tmp/`。上述 artifacts 不提交 Git。

## 7. 开发顺序与交付边界

按 P0 → P1 → P2 → P3 → P4 → P5 推进；P0 先冻结错误成功判定的负例，P4 完成报告实现。每阶段交付当前真实能力、测试、未支持项和下一步，不以整轮任务名宣称全部完成。

第一项实际代码工作是：**固定旧矩形及 8 张多源输入，恢复完整假设图的隔离种子构造入口，同时证明它不会把候选条件提升为可信事实。** 然后修引用和几何实现，最后再决定提示词是否确实需要调整。

计划完成后的成果应是：同一套 ParseGraph 能清楚回答“提取了什么、采用了哪些假设、哪些条件满足、哪些未支持、状态如何构造、重绘是否经审阅正确”。不要求所有真实图片都能重建，但要求每次成功有依据、每次失败可定位。
