# Parser 种子重建首轮修复结果

## 本轮范围

本轮实现修复计划中的候选入口、候选状态隔离、部分布局与数值求解、质量指标纠错。没有完成整个六阶段计划，也没有修改 VLM 提示词、重新采样模型或引入新的 Parser 分支。

使用 `multisource_pipeline_v13_20260923` 已保存的同一批 8 份预测。输入为原图片、题目文本和冻结的模型 ParseGraph；这是后端离线回放，不是新一轮端到端提取评测。模型调用 0 次。

## 实际修改

1. `parser/pipeline.py`：主入口从完整 ParseGraph 构造 proposal seed，admission 继续独立记录。像素拒绝和证据不足不再提前删除候选构造所需条件；未决冲突仍阻止构造。
2. `parser/seed_realizer.py`：候选结果标记 `candidate_instance`、`source_facts_admitted=false` 和所选假设 ID。构造轨迹与物化对象带候选身份及来源图 checksum，不将构造成功等同于原题事实准入。
3. 保留完整观察坐标作为初始化，使用已有数值实现器联合调整约束；观察坐标路径现在也使用数值长度。增加等长、中点残差，修复共线关系仅处理前三点的遗漏，保留边非退化约束。
4. 精确坐标构造后重新检查关系与长度，不再把已识别约束直接填入“满足”列表。共端点的两条线段不能通过退化重叠被判为所需的平行关系。
5. `verifier/trace.py`：等长关系在显式 numeric_witness 模式下按声明容差计算残差；精确状态仍使用严格符号验证。此修改解决约 1e-13 的浮点差异被误判为不等长的问题，没有放宽全部状态的验证。
6. Pipeline/quality 协议升级为 v2。约束满足必须覆盖所有输入关系与数量；目标不是已知前提。原图完整性没有独立参考时为 null，源图重建成功没有审阅依据时为 null。输入侧像素检查明确标记为 input_proposal，不能认证最终重绘。

相关正式修改共涉及 pipeline、seed_realizer、trace verifier、两份测试文件和 `docs/PARSER_PIPELINE.md`。当前仓库另有大量此前未提交的重构改动，本轮没有回退、暂存或提交它们。

## 测试与限制

- 定向测试：40 passed。
- 完整仓库测试：370 passed，66.13 秒。
- 新测试包含旋转布局保持、未准入数量仍参与候选、原图事实边界、遗漏条件不能成功、精确坐标与错误关系冲突，以及数值/精确等长验证的正反例。

尝试直接读取旧 `replay_exact_rectangle_v11` 的 ParseGraph 时，现行严格协议拒绝其旧关系参数角色：`relation:semantic:0 requires one left and one right argument`。本轮没有修改历史 JSON 或增加隐式兼容。当前矩形图来自冻结 v13 预测的数值重建，不能称为已复现旧版精确矩形路径。

局限：数值求解仍使用现有固定迭代预算；圆半径/圆上点耦合、完整 ordered_points 数值处理、区域与目标的物化覆盖、文本与图上标注区分、复杂对象的逐对象完整性评价未在本轮完成。未收敛或不支持不等于数学上无解。完整候选图存在时，也可能只物化其支持的部分，因此不能以 realized 代替原图恢复。
