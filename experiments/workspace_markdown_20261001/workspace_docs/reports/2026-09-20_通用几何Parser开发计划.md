# 通用几何 Parser 开发计划

日期：2026-09-20  
状态：设计与实施依据；本文中的新增能力和验收目标尚未实现。  
开发仓库：`/data/Geosym127K/Geosym-World`。

## 1. 目标与现状

目标是把图片及有限题目文本转换为可查询、可验证、可实现的几何结构：信息不足时保留约束与自由度，条件允许时生成合法几何实例，为 GeoClaw 提供读图工具，为 Geosym-World 提供受控合成种子。

核心流程：

```text
图片 + 可选题目文本
  -> VLM 提取对象、连接、标记、数量、目标与证据
  -> ParseGraph（hypothesis）
  -> 对象绑定、条件准入与冲突检查
  -> 几何约束编译与实现
  -> Geometry State + 验证报告
  -> 重绘 / Agent 查询 / 种子再合成
```

当前已保留 ParseGraph、模型接口、OCR/视觉观察、准入、种子实现器和部分精确补全能力。上轮清理后的全量测试为 341 项通过，这只说明保留代码的测试状态，不代表真实图片解析成功率。

已有案例表明 VLM 输出常含可用信息，但尚无证据说明其普遍正确。当前后端仍存在特定形状补全策略、非精确种子未统一物化 Geometry State、视觉布局与数学约束折中优化等问题。本轮优先建立通用重建能力，再独立衡量提取质量。

## 2. 开发规则

1. **按几何能力开发。** 需求写成“点在线段上、交点分支、角度绑定”等能力，不写成“修复某数据集某题”。数据集名、样本 ID、固定点名不得进入核心判断或提示词分支。
2. **案例只提供证据。** 每次失败先定位到提取、绑定、协议、约束、实现或渲染；修复必须配一个不同布局或不同组合的测试，不能只验原题。
3. **优先组合基本约束。** 矩形等复合概念展开为基本条件；必要的专用构造必须说明数学适用条件，不添加整图匹配模板。
4. **一份语义图、一条主流程。** 复用 ParseGraph 和 Geometry State；求解器内部变量表可以存在，不再建立平行的公共语义协议和多套 admission。
5. **不静默丢信息。** 每个条件都有处理状态；未知关系、未绑定数量和未支持对象保留原始证据并明确诊断。
6. **假设与事实有边界。** 模型输出默认带 confidence/provenance 的 hypothesis；模型自报置信度不视为校准概率，不能单凭高置信度写入事实。
7. **实现成功不认证提取正确。** 构造出满足假设的实例，只证明这些假设在该实例中成立。原题条件、推导结果、种子参数和实例偶然性质分别记录。
8. **简洁、明确失败。** 复用内核、构造器、verifier 和 renderer；不新增隐式兜底、自动重试、级联修补或静默恢复。新增模块必须有独立职责和主链调用者。
9. **保持 Git 边界。** 开发前后检查状态与差异，保留现有未提交改动；只有用户要求时提交，每个 commit 围绕同一目的。凭据、运行产物和临时内容不入 Git。
10. **控制运行成本。** 使用 geosym 环境；先定向测试，再全量测试。模型实验先说明样本、预算、资源、产物和标准；本计划不自动授权大规模运行。

## 3. VLM 提取协议

### 3.1 输入与工作方式

运行输入仅为图片与可选题目文本。答案、解析、formal state、scene metadata、人工参考图只用于离线评测，不能进入提取上下文。

默认一次语义提取。VLM 不生成 Python 或构造代码，不负责判定全局唯一性。数值不完整不能成为拒绝结构提取的理由。OCR/OpenCV 按需提供局部证据，不作为所有样本的强制前置门槛。

提示词按“对象与外框 -> 连接和顺序 -> 标记与数量绑定 -> 文字条件和目标”组织。只包含通用字段、定义和必要示例，不包含数据集规则、内部审计清单或几十种构造模板。

### 3.2 必须能表达的信息

| 类别 | 提取内容 | 协议边界 |
|---|---|---|
| 点 | 内部 ID、可选点名、图中位置、端点/交点关联 | 允许无名点；不要求数学坐标 |
| 线性对象 | 线段/直线/射线、定义引用、关联点及顺序 | 定义不完整可暂存；不能把所有线都当线段 |
| 圆与弧 | 圆心、半径或其他定义条件；弧的起止与方向 | 圆心允许未知；区分优弧、劣弧及歧义 |
| 多边形与区域 | 有序边界、边界方向、孔洞、填充、组合区域 | 边界可以混合线段和弧 |
| 标记 | 直角、平行、等长、等角及同组标记 | 显式绑定作用对象；保留标记位置 |
| 数量 | 长度、角度、半径、面积、周长、弧长、比例等 | 绑定对象，保留原文、表达式、单位或未知值 |
| 文字条件 | 对象定义、关系、数量、逻辑条件 | 区分给定、待证明和求解目标 |
| 歧义 | 名称候选、数字归属、圆弧分支、冲突读法 | 互斥候选不能同时作为成立条件 |

### 3.3 组织规则

- **ID 与标签分离：** ID 在一次解析及后续构造中稳定；可见名称可为空，不由坐标或字母字符串充当唯一身份。更换提取版本时显式记录映射。
- **支持多子图：** 对象属于明确子图；重复点名不自动合并；允许跨子图的相似、全等或数量关系。
- **视觉片段与数学对象分离：** 同一直线的多个片段可以指向同一对象；虚实线、颜色和遮挡是观察属性，不自动推出辅助线、隐藏边或几何事实。
- **拓扑显式化：** 保存端点、关联、顺序、内部/外部和边界；共线不能替代点序。完整线段与子线段具有明确关联。
- **交点有身份：** 确认为几何交点后建立点对象；分支未定或遮挡不明时保留候选。不能把所有像素交叉直接当成数学关联。
- **关系有角色：** 例如点与支撑线、角的顶点与两条射线、相切的对象与接触点、相似图形的顶点对应；采用受控关系类型及参数校验，不能靠自由字符串隐含语义。
- **数量可符号化：** `x+21`、根式、分式和数量方程都保留；提取时不要求解出未知量。表达式通过受限数学 AST 处理，不执行模型生成内容。
- **证据有类型：** 区分题目文字、图中符号、可见连接和外观猜测。像素位置用于绑定和布局；看起来等长、垂直不能直接变成精确条件。

继续使用 `objects / relations / quantities / regions / target / evidence`。实施前逐项审计现有字段；缺少的作用域、角色或状态采用最小版本化扩展，不另建一套公共图结构。

### 3.4 通用性与能力边界

协议必须容纳无名对象、缺少数字、非比例示意图、多子图和未支持语义。协议可表示、实现器可构造、验证器可检查是三个独立能力，维护一张能力表分别声明。

首轮实现限定二维欧氏几何。空间几何需要另外定义空间关联和投影语义；空间图可以保留证据并返回不支持，但不能把投影交叉、角度直接当成空间事实。

## 4. 准入、实现和结果语义

### 4.1 条件如何进入构造

先检查引用、类型和证据绑定，再检查关系间冲突。明确文字和显式标记作为准入候选；仅凭外观的关系保留为未确认解释。准入结果记录依据与尚未验证的内容。

只有通过约定准入规则的条件进入正式实现。可选择展示候选解释，但必须隔离标记，不能通过另一入口绕过准入写入可信状态。提取条件与编译后约束保持可追踪映射。

每条输入条件至少具有下列处理状态之一：

`未决 / 已编译待验证 / 已满足 / 违反 / 不支持 / 冲突 / 已拒绝`

可额外记录该条件用于构造、验证或两者。任何必需条件未处理时，整体不得标为完整成功。

### 4.2 实现策略

1. 将复合概念展开为基本约束，建立对象依赖、变量及必要不等式。
2. 使用现有内核与 ConstructionBuilder 执行可确定构造：中点、比例点、垂足、交点等。
3. 对剩余自由度显式参数化。平移、旋转和必要的尺度规范只是坐标约定，不是题目条件；已知尺度时不能任意归一化长度。
4. 原图布局只用于初始化、选择方向和候选分支。在无法直接构造的耦合约束上使用数值求解，并记录预算与停止原因。
5. 调用独立 verifier 检查所有必需条件、对象完整性、非退化与拓扑，再物化 Geometry State。

基本能力按组合实现：点在线段上使用带区间的参数；直线、射线采用不同参数域；平行/垂直使用方向关系；圆上点使用圆约束；交点保留多解；区域检查边界闭合、自交和孔洞归属。

几何必需条件不能为贴近像素布局而被牺牲。能由参数化精确保证的结构优先精确保证；数值结果按明确的尺度化容差验证，不用显示舍入伪装精确。求解失败、预算耗尽和已证明矛盾分别报告。

### 4.3 三种输出用途，独立的精度说明

| 输出 | 何时提供 | 必备内容 |
|---|---|---|
| 约束表示 | 已提取结构，但未实现或只需要读图信息 | ParseGraph、证据、准入报告、未决项 |
| 合法种子 | 有满足条件的实例，仍有自由度或唯一性未证 | Geometry State、参数选择、约束验证、来源映射 |
| 条件确定的重建 | 对应求解范围内有充分的确定性依据 | Geometry State、确定性依据、镜像等分支说明 |

另行记录精确表达式或数值坐标、容差、残差；精确坐标不等于唯一重建。唯一性未证明时明确写“未知”；单次数值收敛和局部自由度分析不能证明全局唯一。

所有成功种子也必须输出 Geometry State。Renderer 仅从该状态生成图片，禁止再走平行的直接绘图坐标通道。实例选择和实例偶然性质不能成为原题事实；再合成时还需明确保留哪些原条件、允许变化哪些参数。

## 5. 模块职责

| 位置 | 职责与调整方向 |
|---|---|
| `schema/parse_graph.py` | 唯一提取协议、引用与字段校验；最小必要扩展 |
| `parser/openrouter.py`、`prediction.py` | 模型请求、通用提示词、严格解码、预测来源；不承担构造 |
| `parser/ocr.py`、`vision/` | 可选的文字与局部视觉证据；不自行晋升事实 |
| `verifier/parse_graph.py` | 统一准入、绑定依据、冲突与未决项 |
| `parser/constraint_completion.py` | 将现有整图策略逐步收敛为可组合约束和构造依赖 |
| `parser/seed_realizer.py` | 统一调用构造/求解、选择自由参数和输出实例；不复制几何内核 |
| `kernel/`、`construction/`、`solver/`、`verifier/` | 通用数学计算、轨迹执行、求解和独立验证 |
| `rendering/` | 从正式状态绘图与布局标注 |
| CLI 与产物写出 | 只编排调用、打印进度和保存结果；不隐藏业务规则 |

先复用这些模块，不预建新目录或插件框架。每项能力同时说明提取、表示、编译、实现、验证的支持范围。

## 6. 分阶段开发与交付

| 阶段 | 工作与交付 | 完成标准 |
|---|---|---|
| P0：冻结契约 | 审计字段；补角色/子图/匿名对象与状态语义；整理能力表、少量人工参考图和一版通用提示词 | 序列化不丢信息；错误引用可定位；未知条件可保留；不依赖有点名或数值 |
| P1：二维直线闭环 | 点、线段/直线/射线、点序、共线、平行、垂直、中点、比例、长度、交点；统一 Geometry State 和轨迹 | 人工确认的图能实现、独立验证、重放和重绘；自由参数可控，新增条件确实被使用 |
| P2：接通 VLM | 图片与文本到同一协议；完善标记/数量绑定；按需使用局部 OCR/OpenCV；输出紧凑审阅 | 分开报告提取和实现结果；相同输入模式无真值泄漏；错误定位到具体阶段 |
| P3：扩展组合 | 圆、弧、相切、角度、等长/等角、相似/全等、区域孔洞与布尔组合；逐类扩展数量方程支持 | 每类更新能力表，提供独立组合测试；未支持内容不被忽略，部分结果不冒充完整结果 |
| P4：接应用与批量运行 | Agent 查询接口、参数化种子再合成、跨数据集评测、进度与失败分类 | 同一图支持查询/重绘/变参；所有生成实例重新验证；产物和统计可追溯 |

P1 首先使用人工确认的 ParseGraph，排除 VLM 波动；P2 才评估在线提取接入效果。P3 按能力逐项验收，不以“整个圆几何已经支持”等笼统描述交付。高级三维、复杂遮挡和开放世界图形留待本轮闭环稳定后另立计划。

## 7. 通用性测试与验收

### 7.1 两层测试输入

- **实现器层：** 人工确认的 ParseGraph，验证约束编译、合法实例和状态输出。
- **端到端层：** 图片及可选文本，由 VLM 提取，参考信息只进入独立评测器。

开发集和独立审阅集分离。真实图片按结构挑选，覆盖 Geometry3K、MATH-Vision、PGDP 等已有来源；同一母图的变体归同一集合，避免以变体数量夸大泛化。合成图用于可控诊断，不能替代真实图审阅。

### 7.2 必测结构与变化

| 场景 | 检查重点 |
|---|---|
| 无名、无数字的圆与线 | 不依赖点名、完整度量或线段骨架 |
| 延长线、分点与多交点 | 类型、顺序、参数域、分支和退化 |
| 多子图与重复标签 | 对象作用域和跨图对应 |
| 含表达式的边与角 | 原文、表达式、对象绑定和目标区分 |
| 阴影、圆弧边界和孔洞 | 区域语义和边界合法性 |
| 非比例示意图 | 显式条件优先于外观 |
| 缺失、歧义、矛盾或不支持条件 | 保留证据，拒绝假成功 |

每项核心能力增加适当的重命名、旋转、镜像、布局变化或组合测试。变换必须同步调整受影响的量和方向语义；移除标记或数字会减少条件，不能错误要求提取结果完全不变。

### 7.3 指标与通过标准

- 提取：对象/拓扑/关系/数量绑定/目标的准确率和召回率，有无可靠人工参考分别说明。
- 实现：输入条件覆盖、逐条验证结果、退化率、未支持率、失败类型及 trace 重放一致性。
- 端到端：结构正确且全部必需条件满足的比例；保留全部输入作为分母，另列可支持子集指标。
- 重绘：对象与标签完整性、连接、区域及标记正确性；不把像素相似度或成功写 PNG 作为数学正确性。
- 成本：请求数、token、耗时与超时；image-only 和 image+text 使用相同样本配对评测。

确定性正例要求所有必需条件有验证结论，负例不得假成功；通用组合测试和既有全量测试通过。真实数据成功率由新评测实测，不预先宣称达标。首批建议选 12–20 张覆盖不同结构的图审阅，再决定扩大规模；运行前单独说明配置与预算。

## 8. 产物与实施管理

产物位于 `Geosym-World/artifacts/parser/<run_id>/`，默认只保存：

```text
manifest.json       输入版本、代码版本与未提交差异标识、配置、种子、模型/提示词版本、命令
summary.json        指标、计数、失败分类、成本
json/<sample>.json  ParseGraph、准入、实例状态、验证报告、来源和分支信息
images/<sample>/   input、有效重绘、并排 review
debug/             仅显式开启时保存原始响应和细粒度调试信息
```

失败样本输出诊断审阅图，不伪造 redraw；部分候选明确标识。manifest 不含凭据。运行按样本打印进度，统计分母包含失败与超时。旧产物清理只针对归属明确、已有替代且不承担复现依据的内容，不与代码变更混做。

工作区 `docs/internal/` 记录每阶段复现命令、实际结果和未决事项；本计划与能力表按验收结果更新。每轮交付说明新增能力、适用范围、反例、测试与剩余限制，不以某几张图片“看起来正确”代替完成证据。

下一项实施任务：先完成 P0 契约审计和能力表，再建立 P1 的人工约束图测试集；不继续添加样本专属重建策略。
