## 已修复

1. **圆与点采用相同尺度。** 先利用明确的线段长度、半径或直径估计共同尺度，再同时转换观察点与像素半径。数学半径与像素半径分开；已声明的圆上点进入径向约束求解。不会把 `length(circle)` 擅自改成半径。
2. **圆弧进入正式 State。** 中心、起点和终点定义的弧可在隐藏支撑圆上物化，构造轨迹可重放。数值弧必须显式声明容差，最大 `1e-5`；精确构造继续使用严格检查。视口按实际弧段取界，不再强制包含整圆。
3. **先检查明确矛盾。** 已被强制放在同一承载线上的非零线段不能同时垂直；同一对象的相互冲突的长度、半径或直径也会被报告。记录冲突候选 ID，停止生成所谓合法种子。该检查覆盖这些明确矛盾，不是完整的不可满足性求解器。
4. **改进标记和显示。** 等长关系按连通分组生成不同刻线组；直角符号朝向定义线段的内部。Parser 默认关闭推断标记，平行箭头需显式开启；填充仅在 `shaded=true` 时保留，虚线样式通过 State 传递。文本条件仍可参与约束，但不自动全部打印到图上。
5. **修复区域显示策略丢失。** 区域转换保留必要的填充和线型策略，不引入无关元数据变化；原合成视觉回归基线保持通过。
6. **更新通用提取协议。** Prompt 升为 `openrouter-parsegraph-v8`，强调半径/直径类型、圆上点、相切必须结构化输出，以及高度不能误绑到所在斜边。旧响应没有重新生成，因此本次结果不能用来评估新 Prompt 的提取效果。

以上沿用现有 SeedRealizer、ConstructionBuilder、TraceVerifier 和 Renderer，没有增加另一套重建管线。
