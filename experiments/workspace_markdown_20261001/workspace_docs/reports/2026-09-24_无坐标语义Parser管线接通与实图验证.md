# 无坐标语义 Parser 管线接通与实图验证

## 当前流程

```text
原始图片 + 可选题目文本
  -> VLM：点名、点序、连线、关系、测量归属、区域、目标、不确定项
  -> SemanticCompiler：稳定 ID、去重、引用检查、关系展开、严格 ParseGraph
  -> 独立 admission 报告 + 候选状态构造
  -> SeedRealizer / 已有精确补全策略
  -> Geometry State + trace + 独立约束验证
  -> 重绘 PNG + 逐样本 JSON + contact.png
```

新语义不再经过旧的模型格式补救、像素定位和文本补条件流程。VLM 不提供坐标、像素半径或布局提示；候选坐标由代码选择。信息不足时，输出的是满足已有条件的候选实例，而不是声称恢复了原图坐标。

## 修改内容

- `semantic_compiler.py` 直接构造正式 schema 对象，保留原始语义、语句来源与表达式，不再把新协议转换成旧模型输出后再反复修补。
- 保留测量的 image/text 来源；0.5 是未校准的默认置信度，不是模型实际报告的概率。空的可选 unit 字符串规范化为未指定单位。
- `ParserPipeline` 对无坐标协议跳过 PixelTopologyVerifier，即便调用者传入了它。质量报告为 `pixel_topology_not_applicable`，对应 gate 为 null，不计为视觉失败或成功。
- 现有交点补全统一接受 collinear、point_on_line/segment/ray、ordered_points。以前只有共线表达进入补全，导致同一个几何事实换了表达便失效；现在复用已有构造器处理。线段/射线范围仍在候选验证中检查。
- 正式命令增加 `--run-dir`：一次运行完成提取、构造、验证、重绘和自动总览。`--output` 仍是单独的 proposal-only 模式。
- 最大记录数限制尝试次数，失败也计数；无自动重试。保存输入、原始响应、编译结果、候选状态、错误以及复现 manifest。
- 图片请求采用实际 MIME 类型，JPEG 不再被固定标为 PNG。

## 实际调用及失败记录

- 使用 `qwen/qwen3.7-flash`，原图加题目文本；没有 formal state、答案、scene metadata 输入。
- 首轮两个请求：第一条完成，第二条因模型输出空 unit 而编译失败。
- 空单位修复后，仅对受影响的 MATH-Vision 样本进行一次新验证。此次提取结构完整，但暴露了交点补全只识别共线表达的问题。
- 修复交点后，复用已有两份真实模型响应离线重建并生成最终结果，没有再调用模型。
- 合计三次真实请求；每次运行单 worker、temperature=0、无自动重试。最终 final 目录 manifest 明确标为 offline replay、network_requests=0，并记录真实响应来源。
- 首轮失败保留在父目录；后续原始响应保存在 `followup_mathvision/json/raw/`。首轮失败发生时尚未开启逐样本原始响应保存，因此其完整模型响应无法回放；这个诊断缺口已在正式命令修复。
