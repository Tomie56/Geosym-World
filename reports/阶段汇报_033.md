# 阶段汇报 033：面向 Solver-Verified Tool Trace 的 GeoClaw 数据结构升级

## 背景

GeoClaw 不应被定位为计算器、缩放、测量和辅助线的简单组合。已有工作已经充分覆盖单点工具、辅助构造、视觉草图和符号求解。

本轮将仓库进一步收敛到更强的研究定位：

> 由几何 solver 支撑的交互式工具环境，以及对多工具决策轨迹的可审计数据结构和行为评测。

## 新增一等数据结构

### EvidenceRecord

新增统一证据等级：

- `symbolic_proved`；
- `exact_coordinate`；
- `solver_derived`；
- `multi_instance_verified`；
- `numeric_verified`；
- `unknown`；
- `counterexample_found`；
- `invalid`。

这使严格证明、精确坐标验证、多实例数值证据和单实例数值验证不再混为一谈。

### VisualRegion

任务可标注关键视觉区域、涉及对象、用途和是否必要。Zoom tool 会计算 model-selected crop 与 oracle region 的 IoU、覆盖率和 required-region coverage。

### DifficultyProfile

任务难度升级为结构化字段：

- 教育/竞赛层级；
- visual、numeric、construction 或 mixed 类别；
- visual complexity；
- construction depth；
- theorem depth；
- symbolic growth。

这可直接支持“高中立体计算主要依赖 calculator，而奥赛平面证明主要依赖 construct”的分组分析。

## 计算器不再只是数值工具

Calculator tool 现在接受 supporting `fact_ids`，记录：

- fact 是否存在；
- supporting facts；
- expression 是否具有已验证的几何来源；
- 缺少几何支持但最终答案正确的 masking 风险。

新增指标：

- Expression Validity；
- Geometry–Expression Support Rate；
- Calculation Masking Rate。

因此计算器被视为隔离 numerical bottleneck 的工具，而不是主要贡献。

## Zoom 与视觉不确定性

Zoom tool 现在返回：

- 匹配的关键区域；
- best region IoU；
- oracle region coverage；
- required region 是否被覆盖。

新增指标：

- Zoom Grounding IoU；
- Required Region Coverage Rate。

这为 model-selected zoom、oracle zoom 和 random zoom 提供统一评测接口。

## Measurement 与非按比例图风险

Image-mode 的长度和距离通过实际 RenderScene viewport 像素测量。Oracle-mode 读取 exact solver fact。

新增 private audit 通道，保存 visual–solver residual，但不暴露给 Agent observation。由此可计算：

- Visual–Solver Residual；
- Visual Measurement Rate；
- Measurement Reliance Error。

这允许把“过度相信图像近似”作为正式诊断维度。

## Verifier 证据强度

Typed verify 的结果除了 true/false/unknown，还会返回 evidence strength。错误数值声明可被标记为 `counterexample_found`，精确坐标关系与 solver-derived relation 也可区分。

轨迹 scorer 统计每种 evidence level 的分布，为后续 strict proof 与 numeric evidence 对照提供数据接口。

## Private Audit 隔离

TrajectoryStep 新增 private `audit` 字段。完整研究日志可包含：

- oracle measurement value；
- visual–solver residual；
- unsupported geometry expression；
- 后续 parser 或 verifier 的 oracle 对照。

公开轨迹 `include_private=False` 会移除 state summary 和 audit，避免评测时泄漏 GT。

## 批量 Manifest

Batch manifest 现在额外保存每题：

- DifficultyProfile；
- required tool sets；
- visual regions；
- trajectory path；
- termination；
- 完整 step metrics。

这使按题型、构造深度、符号增长和视觉复杂度进行切片分析成为可能。

## 新增指标总览

在原有 Final Accuracy、Tool Selection F1、Argument Validity、Invalid Action Rate、Verified Step Ratio、Useful Action Rate、Tool Efficiency 和 Recovery Rate 基础上，新增：

- Expression Validity；
- Geometry–Expression Support Rate；
- Calculation Masking Rate；
- Zoom Grounding IoU；
- Required Region Coverage Rate；
- Visual Measurement Rate；
- Visual–Solver Residual Mean；
- Measurement Reliance Error；
- Construction Validity；
- Construction Utility；
- Evidence Strength Counts。

## 设计意义

当前数据结构已经能表达以下关键研究问题：

1. 模型是否识别当前瓶颈属于视觉、计算、测量、构造还是验证？
2. 模型是否引用正确的几何对象和 solver facts？
3. 辅助构造是合法且有用，还是合法但冗余？
4. Verify 失败后，模型能否在后续动作内恢复？
5. 最终正确答案是否掩盖了未经支持的计算表达式？
6. 模型是否因非按比例绘图的近似测量产生错误？
7. 最终结论属于严格符号证据、精确坐标证据还是数值证据？

## 当前状态

GeoClaw 已从“有六类工具的环境”升级为“面向 solver-verified tool trace 的数据结构与评测基础设施”。它的评价对象不再是工具是否存在，而是模型能否做出正确、必要、可验证、可恢复的几何决策。
