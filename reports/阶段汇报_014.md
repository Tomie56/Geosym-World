# 阶段汇报 014：Legacy Expected Facts 与 Area/Perimeter 对齐

## 本阶段目标

此前 adapter 已经能把旧 GeoSym record 转成 formal construction trace，并给出 coverage score。但旧 record 里已有的 GT，例如：

- `entities[*].area`
- `entities[*].perimeter`
- `lines[*].length`

还没有作为 expected facts 进入 formal record。

本阶段目标是把这些旧 GT 保留下来，并和新 formal fact closure 做轻量对齐。

## 新增 perimeter facts

`FactClosureSolver` 现在会为 polygon 和 polygon region 生成：

```text
perimeter(object_id)
```

规则：

```text
closed_polyline_perimeter
polygon_region_perimeter
```

这样旧 `entities[*].perimeter` 可以和 formal facts 直接比较。

## 新增 expected helpers

新增：

```text
geosym_world_geometry/expected.py
```

提供两个函数：

```python
legacy_expected_facts(record)
compare_expected_facts(expected_facts, formal_facts)
```

`legacy_expected_facts` 会从旧 record 中抽取：

- `length`
- `area`
- `perimeter`
- `surface_area`
- `volume`
- `radius`

并生成统一 expected fact 结构。

`compare_expected_facts` 会按：

```text
(type, object)
```

查找 formal facts，并比较 symbolic residual：

```text
formal_value - expected_value
```

比较状态包括：

- `matched`
- `missing_formal_fact`
- `value_mismatch`
- `unchecked`

## CLI 输出变化

`tools/adapt_legacy_json.py` 现在会在输出 record 中写入：

```text
adapter.expected_facts
adapter.expected_fact_comparison
```

summary 中新增：

```text
expected_fact_summary
```

## 抽样验证

输入：

```text
datas/synthetic_runs/verify_run/json/final/shaded_with_gt_20260629_183644_296.jsonl
line-index = 1
```

输出：

```text
geosym_world_geometry/outputs/adapted_legacy2d_final_line1_shaded.json
```

结果：

- `verification_valid = true`
- `coverage_score = 0.9474`
- `num_expected = 13`
- `num_matched = 11`
- `num_missing_formal_fact = 2`
- `num_value_mismatch = 0`
- `num_unchecked = 0`

匹配项包括：

- `area(base_parallelogram_3x5) = 15`
- `perimeter(base_parallelogram_3x5) = 6 + 20*sqrt(3)/3`
- `area(translated_parallelogram_edge3) = 15`
- `perimeter(translated_parallelogram_edge3) = 6 + 20*sqrt(3)/3`
- `length(L0...L6)` 全部匹配

缺失项是：

- `area(legacy_shadow_2)`
- `perimeter(legacy_shadow_2)`

原因是旧样本只给出了 shadow GT 和 `shadow_regions = 1`，没有提供 shadow region 的 formal 边界。adapter 因此不能构造对应 region，只能保留 expected fact 并报告 `missing_formal_fact`。

## 当前意义

这一步让旧 GeoSym 的 GT 从“隐含字段”进入 formal record：

```text
legacy record
  -> construction trace
  -> formal facts
  -> legacy expected facts
  -> symbolic comparison
```

后续筛样本时可以区分：

- formal facts 与旧 GT 完全一致；
- formal state 缺失某类对象；
- formal 计算和旧 GT 数值不一致；
- 某些 GT 无法比较。

这比单纯看 final answer 更适合 GeoSym-Debug。
