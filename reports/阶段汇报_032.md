# 阶段汇报 032：GeoClaw 可交互几何 Agent 环境 v0

## 目标

本阶段把现有几何数据结构、solver、verifier 和 renderer 组合为 Agent 的底层交互环境。核心定位是将几何解题表示为可观察、可交互、逐步可验证的工具调用轨迹，而不是把计算器或辅助线本身作为创新点。

## 完成内容

### 统一协议和状态隔离

新增 `AgentAction`、`GeoClawObservation`、`ToolFeedback` 和 `GeoClawTask`。Agent 只提交统一 JSON action。环境内部保存完整 geometry state、FactStore、target 和 answer；模型 observation 只公开题目、图像、crop、对象 ID、历史反馈和预算。

### 六类工具

- `zoom`：归一化区域 crop 和放大，输出 PNG。
- `calculate`：白名单 SymPy 计算，拒绝任意 Python 执行。
- `measure`：支持 image proxy 和 oracle exact 两种模式。
- `construct`：执行中点、垂线、平行线、交点、圆等辅助构造。
- `verify`：typed claim 的 true/false/unknown 验证。
- `final`：符号、数值或文本答案判分并终止 episode。

构造工具采用事务式流程：

```text
base trace + committed agent trace + candidate op
    -> TraceVerifier
    -> ConstructionBuilder
    -> FactClosureSolver
    -> commit or rollback
```

失败动作不会污染 state、facts 或 Agent trace。成功构造会重新渲染 step PNG，因此辅助线和新点自然形成可审计的图上草稿。

### Feedback 和 Utility

反馈状态包括 `valid`、`invalid_schema`、`invalid_argument`、`unknown_object`、`geometrically_invalid`、`unsupported_operation`、`not_verifiable` 和 `execution_error`。

Utility 包括 `progress`、`redundant`、`harmful`、`unknown` 和 `terminal`。合法性与用途分开记录。当前用途依据 target、fact dependencies、任务标注的 acceptable intermediate facts，以及动作前后的 fact closure 增量判断，不依赖唯一标准证明轨迹。

### Parser

v0 实现保守的 Object Reference Resolver：优先精确 ID，再做规范化别名匹配；遇到歧义时拒绝猜测。没有训练 OCR 或完整图像 scene graph parser，从而把 workshop 实验集中在工具决策和 verifier feedback。

### 轨迹和指标

每步保存原始 action、解析 action、feedback、动作前后状态摘要和 step image。Episode 保存终止原因、最终结果和指标。

已实现：

- Final Accuracy；
- Tool Selection Precision / Recall / F1；
- Schema Validity；
- Argument Validity；
- Invalid Action Rate；
- Verified Step Ratio；
- Useful Action Rate；
- Tool Efficiency；
- Recovery Rate；
- Feedback Gain；
- Tool Counts。

连续相关失败被视为一个 failure event，默认检查后续三步内是否出现合法且有用的修正。

### Pilot 和 CLI

新增 10 道确定性任务，覆盖 visual-hard、numeric-hard、construction-hard 和 mixed-hard。每题包含 formal trace、answer、acceptable required tool sets、reference cost、动作预算和类别信息。

运行：

```bash
cd /data/Geosym127K
PYTHONPATH=/data/Geosym127K python -m geosym_world_geometry.tools.run_geoclaw_pilot \
  --task construct_midpoint \

```

## 当前边界

- 主实验仍依赖 oracle formal state。
- image measurement 是 geometry-backed rounded proxy。
- verify 只支持 typed claim。
- pilot 只有 10 题，正式实验需扩展到 120–200 题。
- 尚未绑定模型 API、训练流程或前端。
- 本阶段没有进行大规模数据生成。

## 后续完善

在 v0 基础上继续补充了四项实验基础设施：

1. **工具消融配置**：`GeoClawEnvironment` 支持 `allowed_tools`，可以直接构建 calculator-only、construct-only、zoom-only 或任意组合；`final` 始终保留，禁用工具返回结构化 `unsupported_operation`。
2. **Task fail-fast 校验**：`GeoClawTask.validate()` 和 `require_valid()` 会检查空 trace、非法预算、未知 required tools、trace 可执行性、target 是否可解析，以及符号/数值答案是否与 target 精确一致，避免错误任务进入模型实验后才失败。
3. **真实渲染像素测量**：image-mode 的 length/distance 通过 `RenderScene` 和 `ViewTransform` 获取像素距离，同时返回 `pixel_value` 与换算后的 world value；不再直接等同于 oracle exact 输出。
4. **批量实验 manifest**：新增 `run_geoclaw_batch`，可批量运行 pilot、保存每题 trajectory，并输出配置、aggregate metrics、termination 和路径信息。

Object Reference Resolver 也已经接入 `construct`、`measure` 和 `verify` 工具链。模型可以使用 `point C`、`segment BA` 等别名；解析歧义时环境拒绝猜测，未知引用返回 `unknown_object`。

新增测试后，GeoClaw 专项测试数量从 20 增加到 26。
