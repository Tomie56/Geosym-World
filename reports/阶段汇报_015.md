# 阶段汇报 015：Legacy 3D Expected Facts 抽样对齐

## 本阶段目标

上一阶段已经把旧 2D record 的 `area/perimeter/length` GT 接入 expected facts。本阶段验证旧 3D solved JSON 是否也能进入同一套 expected-fact comparison。

抽样输入：

```text
output/solid_geo_test/json/solid_0000_solved.json
```

输出：

```text
geosym_world_geometry/outputs/adapted_legacy3d_solid_0000.json
```

## 旧 3D 字段结构

该 3D record 包含：

- `points`：28 个 3D 点；
- `edges`：40 条边，带 `length`；
- `faces`：19 个面，带 `area`；
- `entities`：1 个 composite solid，带 `surface_area`；
- `metadata`：3D 生成 metadata。

旧 record 没有直接提供 composite volume GT；volume 仍由新 formal fact closure 计算，并作为 target 验证。

## 本阶段改动

### 1. expected extractor 支持 faces

`legacy_expected_facts` 现在会从以下类别抽 expected metrics：

```text
lines
segments
edges
polygons
faces
regions
polyhedra
circles
entities
```

因此 3D `faces[*].area` 会进入 expected facts。

### 2. 保留 legacy metadata

`LegacyGeometryAdapter` 现在会把顶层：

```text
metadata
```

保存为：

```text
adapter.preserved_metadata.legacy_metadata
```

并将其视为 handled key。这样 3D record 不会因为 metadata 字段被误判为低覆盖。

## 抽样结果

运行：

```text
python -m geosym_world_geometry.tools.adapt_legacy_json \
  --input output/solid_geo_test/json/solid_0000_solved.json \
  --output geosym_world_geometry/outputs/adapted_legacy3d_solid_0000.json \
  --record-id adapted_legacy3d_solid_0000 \
  --question 'Find the volume of composite_1.' \
  --answer '204*sqrt(2)' \
  --target-type volume \
  --target-object composite_1
```

结果：

- `verification_valid = true`
- `coverage_score = 1.0`
- `num_trace_ops = 89`
- `num_facts = 1401`
- `target volume(composite_1) = 204*sqrt(2)`

expected comparison：

- `num_expected = 60`
- `num_matched = 60`
- `num_missing_formal_fact = 0`
- `num_value_mismatch = 0`
- `num_unchecked = 0`

expected facts 分布：

- 40 条 `length`，来自 `edges[*].length`
- 19 条 `area`，来自 `faces[*].area`
- 1 条 `surface_area`，来自 `entities[0].surface_area`

## 当前意义

这说明旧 3D solved JSON 可以进入当前 formal world：

```text
legacy 3D solved JSON
  -> construction trace
  -> 3D formal state
  -> edge/face/polyhedron facts
  -> legacy expected facts
  -> exact comparison
```

同时也验证了当前 3D 接口的保守策略是可用的：即便不做完整 CAD 和渲染，点、边、面、polyhedron 的 metric facts 已经足以承接一批确定性 3D 诊断样本。

## 观察

这条 3D sample 的 exact symbolic comparison 耗时明显高于 2D，主要来自复杂根式表达的化简。当前作为抽样验证可以接受；如果后续批量跑 3D expected comparison，需要增加 fast path，例如先做字符串相等与数值容差检查，再决定是否进入完整 symbolic simplify。
