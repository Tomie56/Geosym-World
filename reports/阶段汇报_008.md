# 阶段汇报 008：Adapter Report

## 本阶段目标

本阶段为 `LegacyGeometryAdapter` 增加结构化适配报告，避免后续接入真实旧 GeoSym 样本时只能通过人工打开大 JSON 查字段。

## 新增能力

`LegacyGeometryAdapter` 现在提供两个入口：

```python
trace = LegacyGeometryAdapter().to_trace(record)
adapted = LegacyGeometryAdapter().adapt(record)
```

其中 `to_trace` 保持旧接口不变，`adapt` 返回：

```text
trace
report
```

## Adapter Report 字段

`report` 当前包含：

- `input_keys`：输入 record 的顶层字段；
- `op_type_counts`：生成的 construction op 类型统计；
- `used_ids`：按类别记录被成功转换的对象 ID；
- `num_skipped`：跳过对象数量；
- `skipped`：跳过对象的类别、ID 和原因；
- `unhandled_top_level_keys`：当前 adapter 没有主动消费的顶层字段。

## CLI 输出变化

`tools/adapt_legacy_json.py` 现在会把 report 写入输出 record：

```text
adapter.report
```

命令行 summary 也会打印：

- `num_skipped`
- `unhandled_top_level_keys`

这能帮助判断某个旧样本是“真正完整适配”，还是只是核心点线面被转换、但一些 GT/阴影/metadata 字段还没接入。

## 当前意义

后续对接旧 GeoSym 样本时，可以按以下顺序推进：

1. 抽一条旧 JSON；
2. 运行 `adapt_legacy_json.py`；
3. 查看 `adapter.report.unhandled_top_level_keys`；
4. 查看 `adapter.report.skipped`；
5. 决定是否扩展字段映射。

这样可以避免盲目大规模跑 adapter。

## 下一步

1. 对旧 2D final JSON 的 `shadow_regions` 做正式区域映射。
2. 对旧 2D final JSON 的 `entities[*].area/perimeter` 做 expected facts 或 validation facts。
3. 对旧 3D solved JSON 的旧 solver volume/surface area 和新 world facts 做数值对比。
4. 给 adapter report 增加 `coverage_score`，用于后续筛掉低覆盖样本。
