# 阶段汇报 016：Expected Comparison Fast Path 与质量标签

## 本阶段目标

上一阶段验证了旧 3D solved JSON 的 expected facts 可以和 formal facts 完整对齐，但也暴露出一个工程问题：

```text
复杂 3D 根式表达如果每条都直接 symbolic simplify，会比较慢。
```

本阶段对 expected comparison 做轻量优化，并增加 record-level quality label，方便后续筛样本。

## Fast Comparison Path

`compare_expected_facts` 现在的比较顺序是：

1. `string_equal`
   - 如果 expected value 和 formal value 字符串完全一致，直接判定 matched。
2. `numeric_tolerance`
   - 如果两边都有 numeric value，且差值在 `1e-8` 内，判定 matched。
3. `symbolic_simplify`
   - 只有前两步不能判定时，才进入 SymPy symbolic residual。

比较结果中新增：

```text
method
```

summary 中新增：

```text
method_counts
numeric_tolerance
```

这能直接看出一个样本主要靠哪种方式完成 expected-fact 对齐。

## Quality Label

`expected_fact_comparison` 现在新增：

```text
quality_label
```

当前标签包括：

- `no_expected_facts`
- `all_matched`
- `partial_missing`
- `has_value_mismatch`
- `partially_unchecked`
- `unresolved`

标签逻辑：

- 所有 expected facts 都 matched：`all_matched`
- 有 mismatch：`has_value_mismatch`
- 没有 mismatch，但缺 formal fact：`partial_missing`
- 没有 mismatch，但存在无法比较项：`partially_unchecked`

这个 label 是 record-level 筛选信号，不替代 trace verifier 或 target lookup。

## 抽样验证

### 2D shaded 样本

输出：

```text
geosym_world_geometry/outputs/adapted_legacy2d_final_line1_shaded.json
```

结果：

- `quality_label = partial_missing`
- `method_counts = {"string_equal": 11, "key_lookup": 2}`
- `num_expected = 13`
- `num_matched = 11`
- `num_missing_formal_fact = 2`
- `num_value_mismatch = 0`

解释：

两个 missing 是 shadow 的 area/perimeter，因为旧 record 没有提供 shadow region 边界。

### 3D solved 样本

输出：

```text
geosym_world_geometry/outputs/adapted_legacy3d_solid_0000.json
```

结果：

- `quality_label = all_matched`
- `method_counts = {"string_equal": 56, "numeric_tolerance": 4}`
- `num_expected = 60`
- `num_matched = 60`
- `num_missing_formal_fact = 0`
- `num_value_mismatch = 0`
- `num_unchecked = 0`

解释：

大部分旧 GT 和 formal fact 的表达式字符串一致，少量复杂等价表达通过 numeric tolerance 判断一致，避免了不必要的 symbolic simplify。

## 当前意义

现在 adapter 输出可以更直接地服务 GeoSym-Hard / GeoSym-Debug 样本筛选：

```text
coverage_score
expected_fact_comparison.quality_label
expected_fact_comparison.method_counts
verification_valid
target_fact
```

这些字段组合起来可以区分：

- 高覆盖且全部 GT 匹配；
- 高覆盖但缺 formal object；
- formal 计算与旧 GT 不一致；
- 没有足够 expected facts 的样本。
