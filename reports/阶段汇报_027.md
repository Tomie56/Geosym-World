# 阶段汇报 027：Completion Audit 与后续路线

## 本阶段目标

这一步不是继续扩功能，而是对照最初需求做一次 completion audit，确认当前 `geosym_world_geometry/` 是否已经形成一个可维护、可验证的 formal geometry prototype。

最初硬性要求包括：

- 所有新代码、文件、数据放在 `geosym_world_geometry/`；
- 建 `geosym/formal/` 方向的 skeleton；
- 定义 `ConstructionOp` / `FormalState` / `Fact` schema；
- 实现 `add_point`、`add_segment`、`add_polygon`、`midpoint`、`intersection`、`perpendicular_through`、`set_target`；
- 实现距离、角度、面积、平行、垂直 fact closure；
- 增加正常有角度的相交、中点、角平分线等能力；
- 为立体几何先把接口留好；
- 开发中维护 clean、可读，并阶段性写中文 md 汇报。

因此当前可以视为“formal geometry world v0 prototype”阶段完成，可以进入下一阶段：从 prototype 向稳定数据引擎演进。

## 仍需明确的边界

当前系统不是完整 synthetic proof engine。它依赖 SymPy 坐标与符号表达式做 exact check 和 fact closure。

自动截面目前处理一般边-平面相交与排序，但对共面边、重合面、复杂非凸多面体等退化情形仍是保守实现。

当前验证是 smoke-level，不是完整单元测试矩阵。它适合防止关键能力退化，但不能替代后续系统测试。

legacy adapter 已有样例和输出，但还不能承诺覆盖所有历史 JSON 变体。

## 后续建议

下一阶段建议不要继续盲目扩 op，而是按下面顺序推进：

1. **Unit test matrix**：把 construction ops、fact families、3D section/projection 拆成 pytest 单测。
2. **Data engine design**：定义 problem template、difficulty policy、sampling policy、invalid-case rejection。
3. **Renderer contract**：把 formal state 到 diagram/render metadata 的接口固定下来。
4. **Proof/derivation layer**：在 coordinate-backed facts 之上增加更稳定的 derivation graph，而不是只导出一组 facts。
5. **Hard benchmark design**：围绕 geometry hallucination、auxiliary construction、long-horizon reasoning、3D section 四类任务设计小规模 curated benchmark。
